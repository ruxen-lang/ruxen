# E1700 — unrecognised regex flag

A `/pat/flags` regex literal carries a flag character that isn't
recognised or repeats an already-seen flag. The accepted flag set is
`i m s g x`; any other ASCII letter trailing the closing `/` — or a
duplicate of one of the five — triggers this error.

## Why

Ruxen pins the regex flag alphabet to the five characters PCRE2
exposes through its compile options (`i` → `PCRE2_CASELESS`, `m` →
`PCRE2_MULTILINE`, `s` → `PCRE2_DOTALL`, `x` → `PCRE2_EXTENDED`)
plus `g` which the JS/Ruby surface uses as a marker without backing
state. Anything else would silently fail at runtime or — worse —
get interpreted as a PCRE2 option by a future PCRE2 version we
hadn't audited. Catching the typo at lex time also keeps `/foo/g1`
from being mis-tokenised as a regex followed by a name. Duplicate
flags are rejected for the same reason: silently dropping the
second `i` papers over a real bug in the user's intent.

## Example (rejected)

```ruxen
let r = /foo/q   # E1700: unrecognised regex flag 'q'
let s = /bar/ii  # E1700: regex flag 'i' specified more than once
```

## Fix

Drop the offending letter or replace it with one of the supported
flags:

| Flag | Effect                                                        |
|------|---------------------------------------------------------------|
| `i`  | case-insensitive                                              |
| `m`  | multi-line — `^` and `$` match per-line, not just per-input   |
| `s`  | dot-all — `.` matches `\n`                                    |
| `g`  | global — accepted, no behavioural effect (use `.scan` /       |
|      | `.replace_all` instead)                                       |
| `x`  | extended — whitespace + `#` comments allowed inside the body  |

Each flag may appear at most once per literal.
