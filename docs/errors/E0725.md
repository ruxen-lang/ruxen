# E0725 — stdlib bootstrap failed

## Summary

The compiler tried to parse a stdlib `.rvn` file at startup and could
not. This is a **fatal compiler error**, not a user-source error: it
means the Riven standard library that ships with `rivenc` is itself
broken in this environment, so user code cannot be compiled until the
stdlib is fixed.

The diagnostic always cites the stdlib file and line involved, e.g.:

```
[E0725] error: stdlib bootstrap failed at library/std/src/io.rvn:42: parser: expected `def`, found `end`
```

## Common causes

1. **Stale `RIVEN_STDLIB_PATH`.** The environment variable points at a
   directory that is missing files in the bootstrap list, contains an
   old grammar revision, or is not actually a stdlib root. Unset it
   (`unset RIVEN_STDLIB_PATH`) and re-run; the compiler falls back to
   the workspace `library/std/src/` next to `rivenc`.

2. **In-tree stdlib edit broke the parser.** You edited a file under
   `library/std/src/` and introduced a syntax error. Re-read the
   cited file at the cited line; the message after the colon names the
   exact lexer or parser failure (`expected NAME`, `unterminated
   string`, etc.).

3. **Installed sysroot is corrupt.** A partial install left some
   stdlib files missing or truncated. Re-run the installer or
   re-checkout the workspace.

## How to fix

- If the message says `cannot read file: …`, the file is missing or
  permissions block it. Verify with `ls -la <path>`.
- If the message says `lexer: …`, a token-level malformation
  (unterminated string, invalid escape, malformed numeric literal).
  Fix the cited line.
- If the message says `parser: …`, a structural problem (missing
  `end`, unexpected token, malformed signature). Fix the cited line.

## Background

The Riven compiler's stdlib lives in `.rvn` source files under
`library/std/src/` (post #06.8 stdlib self-hosting). They are parsed
by the **same parser** user code goes through, so any grammar change
that breaks user fixtures also breaks stdlib — and the bootstrap
loader is the first place that fails when it does. That is by
design: it surfaces stdlib breakage immediately and loudly rather
than letting it bleed into confusing downstream type-check errors.
