# E1117: class includes a `dispatch runtime` mixin but is missing required methods

## Why
A mixin marked `dispatch runtime` opts into per-implementor vtable
dispatch (see [docs/specs/types/mixin_vtables.spec.md](../specs/types/mixin_vtables.spec.md) §B1).
Every required method on such a mixin becomes a slot in the
implementor class's vtable; the runtime helper assumes every slot is
populated. If an `include`r fails to implement a required method,
there is no compile-time fallback — the call site would dispatch
through a null function pointer.

The static-dispatch path tolerates structural satisfaction (and even
silently drops the requirement in some cases today). Runtime-dispatch
mixins do not: missing methods are always an error.

## Example
```rx
mixin Future dispatch runtime
  type Output
  def var poll(cx: &var Context) -> Poll[Self.Output]
end

class TimeSleep
  include Future
  # error[E1117]: class `TimeSleep` includes runtime-dispatch mixin
  # `Future` but is missing required method(s): `poll`
end
```

## Fix
Implement every method the mixin declares as a signature.

```rx
class TimeSleep
  include Future
  type Output = Unit

  def var poll(cx: &var Context) -> Poll[Unit]
    Poll.Ready(())
  end
end
```

If the method is genuinely optional, declare it with a default body
in the mixin rather than as a bare signature — default-bodied methods
do not trigger E1117.

## Notes
- E1117 only fires for mixins explicitly marked `dispatch runtime`.
  Ordinary mixins still use the structural-satisfaction path.
- Spec: [docs/specs/types/mixin_vtables.spec.md](../specs/types/mixin_vtables.spec.md) §B1 + "Reserved error codes" §E1117.
- Companion code: [E1118](E1118.md) — `&Mixin` referencing a non-runtime-dispatch mixin.
