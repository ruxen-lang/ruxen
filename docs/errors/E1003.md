# E1003: cannot borrow as immutable — already borrowed as mutable

## Why
This code is no longer emitted. Loans are checked on MIR
(`mir/loan_check.rs`), which reports a conflicting borrow by what the
program does to the borrowed place: E1002 when a `&var` or `var self` call
can change it while a view of it is still used, E1009 when it is written or
moved. The code stays registered so it keeps its meaning.

## Example
A shared borrow next to a live `&var` of the same variable is not an error
by itself. A `&var` of an object, an Array or a Hash is its handle, so a
read through `&v` after a `push` through `&var v` reads the same object:

```rx
def run -> nil
  v = [1, 2]
  m = &var v
  r = &v
  m.push(3)
  puts r.size   # 3
end
```

What is rejected is a view that the write would leave dangling:

```rx
def replace(s: &var String) -> nil
  s = "replaced"
end

def run -> nil
  s = "abc"
  m = &var s
  r = &s
  replace(m)   # E1002: `s` is replaced while `r` still views it
  puts r
end
```

## Fix
See E1002 and E1009: use the view before the write, or clone it.
