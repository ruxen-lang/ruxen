# E0712: SeekFrom arg out of range (negative offset on Start)

## Why
`SeekFrom.Start(n)` names an absolute file position. Positions before
byte 0 are undefined — `lseek(fd, n, SEEK_SET)` with `n < 0` returns
EINVAL. The other two variants (`End(n)` and `Current(n)`) accept
negative offsets (they relativise from the file end and current
position respectively), so this restriction is specific to `Start`.

## Example
```rvn
# error[E0712]: SeekFrom arg out of range (negative offset on Start)
let _ = file.seek(SeekFrom.Start(-1))
```

At runtime the error surfaces as
`Result.Err(IoError.InvalidInput(_))`. The `.message()` payload
identifies E0712 as the cause:
`"SeekFrom.Start(n) requires n >= 0 (E0712)"`.

## Fix
- Use `SeekFrom.End(n)` if you want to seek `n` bytes before the end.
- Use `SeekFrom.Current(n)` if you want to seek `n` bytes backward
  from the current position.
- Pin the position at 0:
  ```rvn
  let _ = file.seek(SeekFrom.Start(0))
  ```

## Notes
- Static (compile-time) detection is restricted to literal-only cases
  (`SeekFrom.Start(-1)`) — the more common runtime-computed offset
  case demands a runtime check. We ship the runtime check first; a
  literal-only static check can piggyback on a future const-folding
  pass.
- `lseek(2)` may also return EBADF, EOVERFLOW, ENXIO. Those surface
  via the normal errno classifier (`IoError.from_errno`) and yield
  the matching variant (`InvalidInput`, `InvalidData`, `Other`).
- Wire layout for `SeekFrom` is the standard 16-byte tagged enum
  shape: `{i32 tag; i32 _pad; i64 offset}`. Tags 0/1/2 map to
  `SEEK_SET / SEEK_END / SEEK_CUR` and are pinned by the
  `file_class_layout_stability` test.
