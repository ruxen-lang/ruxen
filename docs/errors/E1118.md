# E1118: `&Mixin` references a non-`dispatch runtime` mixin

## Why
The `&Mixin` / `&var Mixin` parameter / field type denotes a
dyn-shape reference: at runtime the receiver is identified through
the mixin's vtable. Only mixins marked `dispatch runtime` carry
a vtable — see [docs/specs/types/mixin_vtables.spec.md](../specs/types/mixin_vtables.spec.md) §B1, §B7.

Statically-dispatched mixins have no vtable and no runtime identity,
so a `&Mixin` reference to one would be unusable. Rather than silently
fall back to a static type-erased pointer (which would lose the
ability to call mixin methods), the compiler rejects the form
outright and asks the author to opt the mixin into runtime dispatch.

## Example
```rx
mixin Drawable
  def draw -> ()
end

def render_all(items: Array[&Drawable]) -> ()    # error[E1118]
  ...
end
```

## Fix
Either:

1. Opt the mixin into runtime dispatch:
   ```rx
   mixin Drawable dispatch runtime
     def draw -> ()
   end
   ```

2. Or, if heterogeneous dispatch isn't needed, drop the indirection
   and accept a concrete type or `some Mixin` / `any Mixin`:
   ```rx
   def render_one(item: some Drawable) -> ()    # static dispatch
     ...
   end
   ```

## Notes
- E1118 is emitted at name-resolution time on the type-expression
  itself; the diagnostic span covers the entire `&Mixin` reference.
- Spec: [docs/specs/types/mixin_vtables.spec.md](../specs/types/mixin_vtables.spec.md) §B7 + "Reserved error codes" §E1118.
- Companion code: [E1117](E1117.md) — runtime-dispatch mixin missing required methods.
