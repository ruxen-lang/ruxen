# E0606: Ord implies Eq and PartialOrd — synthesize them together

## Why
`Ord` is the total-ordering refinement built on top of `Eq` and
`PartialOrd`. Synthesizing `cmp` is meaningful only when the
related equality and partial-order mixins are also satisfied. The
compiler's auto-synthesis path expects the full stack to be
consistent.

The diagnostic surfaces when a user override breaks the lockstep —
for example, defining a custom `cmp` whose shape diverges from
the synthesized `PartialOrd.partial_cmp` on the same type.

## Example
```rvn
struct Version
  major: Int
  minor: Int

  def cmp(other: &Version) -> Ordering
    self.major.cmp(&other.major)        # ignores minor
  end
end                                      # error[E0606]
```

## Fix
Either drop the override (let auto-synth supply lex-order over
every field) or define the entire stack consistently:

```rvn
struct Version
  major: Int
  minor: Int       # auto-synth: PartialEq, Eq, PartialOrd, Ord all lex
end
```
