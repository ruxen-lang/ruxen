# E0606: Ord implies Eq and PartialOrd — synthesize them together

## Why
`Ord` is the total-ordering refinement built on top of `Eq` and
`PartialOrd`. A type body that says `include Ord` therefore also needs
`include Eq` and `include PartialOrd` (and `Eq` needs `PartialEq`,
E0604); the compiler does not add the missing ones for you.

All four mixins are Rust vocabulary and are [deprecated]. The Ruby
form is `include Comparable` plus a `<=>` method, which gives `<`,
`<=`, `==`, `>`, `>=`, `between?` and `clamp`.

## Example

A [deprecated] `include Ord` on its own, rejected with E0606:

```ruby
class Version
  major: Int
  minor: Int
  include Ord       # needs Eq and PartialOrd too
end
```

## Fix
Include `Comparable` and define `<=>`.

Compiles [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Version
  major: Int
  minor: Int

  def init(major: Int, minor: Int)
    @major = major
    @minor = minor
  end
  include Comparable

  def <=>(other: &Version) -> Int
    if major == other.major
      minor <=> other.minor
    else
      major <=> other.major
    end
  end
end

puts Version.new(1, 2) < Version.new(1, 3)
```
