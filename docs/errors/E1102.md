# E1102: SharedSync requires Send payload

## Why
`SharedSync[T]` is a reference-counted wrapper for sharing values
across threads. The contained type `T` must implement
`Send`. The compiler found a construction whose payload type does
not.

The wrapper itself doesn't allow mutable sharing, so `Sync` is
NOT required of `T` — only `Send` (the cross-thread move is the
constraint).

See [docs/specs/ownership/send_sync_enforcement.spec.md](../specs/ownership/send_sync_enforcement.spec.md)
§B4 for the rule.

## Example

Rejected with E1102 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Foo
  n: Int

  def init(n: Int)
    @n = n
  end
end

f = Foo.new(1)
_s = SharedSync.new(f)       # E1102: Foo is not Send
```

## Fix
User classes are not automatically `Send` in v1. If the class is
genuinely safe to share across threads, add an explicit `include
Send`.

Compiles [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Foo
  n: Int

  def init(n: Int)
    @n = n
  end
  include Send
end

f = Foo.new(1)
_s = SharedSync.new(f)
```

For classes wrapping raw pointers or non-Send foreign handles, use
`unsafe include Send` to manually assert safety.

Compiles [implemented]:

```ruby
class WrapsRawPointer
  ptr: *UInt8
  unsafe include Send
end
```
