# E1102: SharedSync requires Send payload

## Why
`SharedSync[T]` is a reference-counted wrapper for sharing values
across threads (the canonical name for the v1 `Arc` rename per
ruby-naming spec §10a). The contained type `T` must implement
`Send`. The compiler found a construction whose payload type does
not.

The wrapper itself doesn't allow mutable sharing, so `Sync` is
NOT required of `T` — only `Send` (the cross-thread move is the
constraint).

See [docs/specs/ownership/send_sync_enforcement.spec.md](../specs/ownership/send_sync_enforcement.spec.md)
§B4 for the rule.

## Example
```rvn
class Foo
  def init
  end
end

def main
  let f = Foo.new
  let _s = SharedSync.new(f)   # E1102: Foo is not Send
end
```

## Fix
User classes are not auto-derived for `Send` in v1. If the class is
genuinely safe to share across threads, add an explicit `include
Send`:

```rvn
class Foo
  include Send
  def init
  end
end
```

For classes wrapping raw pointers or non-Send foreign handles, use
`unsafe include Send` to manually assert safety:

```rvn
class WrapsRawPointer
  unsafe include Send
  def init
  end
end
```
