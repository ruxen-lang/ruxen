# E0702: non-const expression in const-arg position (reserved)

**Status:** reserved by `docs/specs/types/const-generics.spec.md`
§"Error code reservations".  No emit site today; planned to fire
when the expression supplied at a const-arg slot references a
*runtime* binding rather than a const literal or a const param.

## Why (planned)

Const-generic arguments must be resolvable at compile time.  A
runtime `let n = read_input()` value cannot be plugged into
`Vector[Int, n]` because monomorphization happens before that value
exists.

Per spec §B8 the accepted shapes are integer literals, references
to const-generic parameters, and `+ - * /` arithmetic over those.
Anything else is non-const and rejected here.

## Example (planned)

```rvn
def make_vec(n: USize) -> Vector[Int, n]
  Vector[Int, n].new   # error[E0702]: `n` is a runtime parameter
end
```

## Fix (planned)

Promote the value to a const generic parameter on the surrounding
declaration:

```rvn
def make_vec[const N: USize] -> Vector[Int, N]
  Vector[Int, N].new
end
```

Or, when the value is a compile-time constant, declare it via
`const`:

```rvn
const N: USize = 4
let _v = Vector[Int, N].new
```

## Notes

- Const-generic *inference* is non-goal OQ-3 — the compiler will
  never guess `N` from context.  Users must spell out the const
  argument explicitly at every use site.
- This is distinct from **E0701** (wrong const-arg *type*) and
  **E0700** (kind mismatch).
