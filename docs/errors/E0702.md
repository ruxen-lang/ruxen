# E0702: expression is not a valid v1 const expression

## Why
Const expressions in const-generic argument positions
(`Vector[Int, ...]`) and array-size slots (`[T; ...]`) must fold to
a `u64` at compile time.  The v1 const language is intentionally
narrow:

- integer literals;
- references to in-scope `const N: TY` generic parameters;
- `+ - * /` arithmetic over those (with parens for grouping).

Anything else — `%` and other unsupported binary operators
(comparisons, `&&`, bit / shift), function calls, method calls,
field accesses, runtime variable references — surfaces as E0702 at
the resolve site.

The lowerer (`resolve::lower_const_expr_from_expr`) maps unsupported
shapes to a `ConstExpr::Error` marker; resolve walks the resulting
tree and emits one E0702 per construction site (at most one — nested
markers don't compound).

## Example: unsupported operator
```rx
struct Buf
  data: [Int; 5 % 2]   # error[E0702]: % is not in v1 const language
end
```

## Example: function call
```rx
def count -> Int; 4; end

struct Buf
  data: [Int; count()]   # error[E0702]: not a const expression
end
```

## Example: comparison
```rx
def main
  let _x: Vector[Int, 3 < 4] = Vector.new  # error[E0702]
end
```

## Fix
Reach for a supported shape:

- For arithmetic, stick to `+ - * /`.  `%` can often be rewritten:
  `[T; (N + 1) - N]` instead of `[T; (N + 1) % 1]`.
- For computed sizes, promote the value to a const-generic parameter
  on the surrounding declaration:

  ```rx
  def make_buf[const N: USize] -> [Int; N]
    [0; N]
  end
  ```

- For derived constants that *are* compile-time values but use
  unsupported syntax, declare them as a `const`:

  ```rx
  const SIZE: USize = 4
  struct Buf
    data: [Int; SIZE]
  end
  ```

## Notes
- Const-generic *inference* is non-goal OQ-3 — the compiler will
  never guess a const argument from context.  Users must spell out
  the const argument explicitly at every use site.
- Distinct from **E0703** (overflow / div-zero on otherwise-valid
  arithmetic), **E0704** (kind mismatch — type vs. const slot), and
  **E0705** (const-param declared with a non-integer / non-Bool
  type).
- v1 limit by spec §B8; v2 may admit `%` and bit operations once
  the const evaluator gains those branches.
