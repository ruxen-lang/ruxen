# E0711: OpenOptions requires at least one of read/write/append

## Why
`OpenOptions` is the builder for `File.open_options(path, opts)`. The
underlying `open(2)` syscall requires the caller to choose an access
mode — `O_RDONLY`, `O_WRONLY`, or `O_RDWR`. Calling
`File.open_options(path, opts)` with an `OpenOptions` value that has
none of `.read(true)`, `.write(true)`, or `.append(true)` set cannot
be mapped to a valid `open(2)` flag set.

## Example
```rvn
# error[E0711]: OpenOptions requires at least one of read/write/append
let opts = OpenOptions.new().create(true)
match File.open_options("/tmp/x", opts)
  Ok(_)  -> puts "ok"
  Err(e) -> puts "err: #{e.message}"
end
```

At runtime the error currently surfaces as
`Result.Err(IoError.InvalidInput(_))` so existing match arms work
unchanged. The `.message()` payload identifies E0711 as the cause:
`"OpenOptions requires at least one of read/write/append (E0711)"`.

## Fix
Pick at least one access mode:

```rvn
let opts = OpenOptions.new().read(true)
let opts = OpenOptions.new().write(true).create(true)
let opts = OpenOptions.new().append(true).create(true)
let opts = OpenOptions.new().read(true).write(true).create(true)
```

## Notes
- Static (compile-time) detection of this error is deferred until a
  const-folding pass over the OpenOptions chain lands; today's
  `OpenOptions.new().read(true)` chain is a value-level expression
  that a single-AST-pass static analysis would have to flow-sense
  to read accurately. The runtime check is always authoritative.
- The flag matrix mirrors Rust's `std::fs::OpenOptions`:
  | read | write | append | open(2) flags          |
  |:----:|:-----:|:------:|:-----------------------|
  |  1   |   0   |   0    | `O_RDONLY`             |
  |  0   |   1   |   0    | `O_WRONLY`             |
  |  1   |   1   |   0    | `O_RDWR`               |
  |  *   |   *   |   1    | `O_WRONLY/O_RDWR | O_APPEND` |

  `.truncate(true)` adds `O_TRUNC` (only honored with write or
  append). `.create(true)` adds `O_CREAT` (mode 0644).
  `.create_new(true)` adds `O_CREAT | O_EXCL` (overrides `.create`).
