# E0700: `sum` requires elements that implement `Add`

## Why
`Array#sum` is defined only when the element type satisfies `Add`
(a numeric `+` operation with an additive identity). The runtime sums
the raw 64-bit slot of each element. For `Array[String]`,
`Array[Array[_]]`, `Array[Hash[_, _]]`, or any user class, those slots
hold pointers — adding pointer addresses produces nonsense, not a
meaningful aggregate.

Ruxen rejects the call at type-check rather than at runtime so the
diagnostic points at the source span instead of producing a silently
wrong answer at execution time.

## Example
```rx
def main
  let v: Array[String] = ["a", "b"]
  let s = v.sum   # error[E0700]: `String` is not numeric
end
```

## Fix
Pick the right method for the element type:

* **Integer / float elements** — already accepted; no change needed.
* **Joining strings** — use `Array#join` instead of `sum`:
  ```rx
  let parts = ["a", "b", "c"]
  let joined = parts.join(", ")
  ```
* **Custom aggregates** — use `reduce` with a zero value and an explicit
  combiner:
  ```rx
  let total = items.reduce(0) { |acc, x| acc + x.cost }
  ```

## Notes
- An element type that is not yet known passes without rejection: it
  is either pinned by a later constraint (still numeric, so accepted)
  or reported by its own diagnostic.
