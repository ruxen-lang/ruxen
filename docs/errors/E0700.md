# E0700: iterator `sum` requires an Item that implements `Add`

## Why
`Iterator::sum` is defined for iterators whose `Item` type implements
`Add` (i.e. has a numeric `+` operation with an additive identity).
The v1 runtime backs `*Iter.sum` with `riven_vec_sum`, which integer-
sums the raw 64-bit slot of each element. For `Vec[String]`,
`Vec[Vec[_]]`, `Vec[HashMap[_,_]]`, or any user class, those slots
hold pointers — adding pointer addresses produces nonsense, not a
meaningful aggregate.

Riven rejects the call at type-check rather than at runtime so the
diagnostic points at the source span instead of producing a silently
wrong answer at execution time.

## Example
```rvn
def main
  let v: Vec[String] = vec!["a", "b"]
  let s = v.iter.sum   # error[E0700]: `String` is not numeric
end
```

## Fix
Pick the right terminator for the Item type:

* **Integer / float Items** — already accepted; no change needed.
* **Joining strings** — use `String::join` over the materialised
  collection instead of `sum`:
  ```rvn
  let parts = vec!["a", "b", "c"]
  let joined = parts.join(", ")
  ```
* **Custom aggregates** — use `fold` with a zero value and an explicit
  combiner:
  ```rvn
  let total = items.iter.fold(0) { |acc, x| acc + x.cost }
  ```

## Notes
- `Ty::Infer` element types pass through without rejection — they
  will either be pinned by a downstream constraint (still numeric and
  thus accepted) or already surfaced as a separate diagnostic.
- The trait-driven dispatch story (full `Iterator` + `Add` traits in
  `.rvn` stdlib source) is deferred to prompts 07/09; until then the
  built-in arm in `typeck::infer::builtin_method_type` carries the
  guard.
