# E0610: derive: field type does not satisfy the derived trait's bound

## Why
A `derive(...)` attribute can only synthesize an impl when every
field type itself implements the trait being derived. This generic
diagnostic fires when the synthesizer reaches a field whose type
fails the bound — for example, `derive Clone` on a struct whose
field is an extern type that is not `Clone`.

## Example
```rvn
extern type RawHandle

@[derive(Clone)]
struct Wrapper
  inner: RawHandle
end
```

## Fix
Either remove the offending derive, or change the field to a type
that does satisfy the bound (often by wrapping it in a `Clone`-able
container or implementing the trait manually):

```rvn
@[derive(Clone)]
struct Wrapper
  inner: Int
end
```
