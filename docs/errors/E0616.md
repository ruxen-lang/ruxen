# E0616: auto-synth Default: enum's first variant has fields without Default

## Why
A synthesized `Default` for an enum has to pick a variant to build.
An enum with no variants at all has nothing to pick, so
`include Default` on it is rejected with E0616. (An enum that has
variants but no way to mark one as the default reports E0605.)

Both pieces are Rust vocabulary: `enum` is [deprecated] (replaced by
symbols and `Data` variants, [planned](../../TODO.md#t-data-define)),
and so is the `Default` mixin (replaced by arguments with defaults).

## Example

A [deprecated] empty `enum` that includes `Default`, rejected with E0616:

```ruby
enum Resource
  include Default    # no variant to build
end
```

## Fix
Give the enum its variants and drop `include Default`; name the default
where it is needed, for example as an argument default.

The [deprecated] `enum` with an argument default compiles:

```ruby
enum Resource
  Closed
  Open
end

def track(state: Resource = Resource.Closed)
  puts "tracked"
end

track()
```
