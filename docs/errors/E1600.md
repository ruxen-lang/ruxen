# E1600: workspace member not found

## Why
A `[workspace] members = [...]` entry resolves to a directory that
does not exist on disk, or that exists but lacks a `Ruxen.toml`.
The package manager surfaces this at the start of any `ruxen build`
inside the workspace so a typo in the workspace declaration fails
loudly instead of silently dropping a member.

The same code covers an unsupported glob shape: only a trailing
`/*` is accepted in v1 (e.g. `"examples/*"`). Embedded `*`, `**`, or
`?` patterns are rejected.

## Example
```toml
# Ruxen.toml at the workspace root
[workspace]
members = ["pkg-a", "pkg-b", "examples/*"]
```

If `pkg-b/` does not exist:
```
error[E1600]: workspace member `pkg-b` declared in [workspace] members,
              but `<root>/pkg-b/Ruxen.toml` does not exist
```

## Fix
- Create the missing member with `ruxen new pkg-b --lib` (or `--bin`).
- Remove the stale entry from `[workspace] members`.
- For globs, ensure the parent directory exists and contains
  subdirectories each holding their own `Ruxen.toml`.

## Notes
- Emitted by the workspace-member expansion pass in
  `ruxen_cli::manifest::expand_workspace_members`.
- Companion code: [E1601](E1601.md) — circular path dependency.
