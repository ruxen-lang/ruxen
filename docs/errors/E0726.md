# E0726: function reference needs arguments; call it or annotate a `Fn` type

## Why

Ruby calls a method named without arguments: `names` and `names()` mean
the same thing. Ruxen follows that for a bare reference to a function
in a value position whose expected type is **not** a function type: it
is a call with zero arguments. Today that auto-call is reliable only
when the context fixes the type; a bare zero-argument call used as a
plain value (`puts five`) still passes the function itself, and is
[planned](../../TODO.md#t-f45). Write the parentheses for a
zero-argument call until then.

The auto-call only makes sense when the function takes zero arguments.
The moment a function requires one or more arguments, an auto-call with
zero arguments would either be ambiguous (which argument was
forgotten?) or wrong (`f` was clearly meant as a reference, not a
call). Ruxen refuses to guess. E0726 fires so the call site stays
explicit: either *call* the function with its required arguments, or
*reference* it under a `Fn` type so auto-call is suppressed.

## Example

A zero-argument call, with the parentheses written out, compiles [implemented]:

```ruby
def names -> Array[String]
  ["a", "b"]
end

argv = names()
puts argv.size
```

A function with arguments cannot auto-call.

Rejected with E0726 [implemented]:

```ruby
def add(a: Int, b: Int) -> Int
  a + b
end

f = add              # error[E0726]: `add` needs 2 arguments
```

## Fix

**Call it** — supply the arguments.

Compiles [implemented]:

```ruby
def add(a: Int, b: Int) -> Int
  a + b
end

sum = add(1, 2)
puts sum
```

**Reference it**: a bare `add` under a `Fn`-typed parameter typechecks
(the `Fn` context suppresses auto-call), but the program it builds does
not run correctly today: calling the parameter as `f(1, 2)` fails to
link, and `f.call(1, 2)` crashes. Passing a named function as a value is
a [known issue](../../TODO.md#t-fn-ref-value). Until it is fixed,
wrap the function in a lambda.

Compiles and prints `3` [implemented]:

```ruby
def add(a: Int, b: Int) -> Int
  a + b
end

def apply(f: Fn[(Int, Int) -> Int]) -> Int
  f.call(1, 2)
end

puts apply(-> (a: Int, b: Int) { add(a, b) })
```

The same applies whenever a function is passed to a higher-order
function: if the parameter is `Fn`-typed, a bare name is not
auto-called; otherwise it is auto-called and its result is passed.
