# E0726: function reference needs arguments; call it or annotate a `Fn` type

## Why

Ruxen auto-calls a bare reference to a function or method when it is used in a
value position whose expected type is **not** a function type. For a function
that takes zero arguments this is seamless — `args` and `args()` mean the same
thing in a non-`Fn` context. The compiler enforces this everywhere so top-level
definitions read like values when they are values.

That trick only works when the function takes zero arguments. The moment a
function requires one or more arguments, an auto-call with zero arguments would
either be ambiguous (which argument was forgotten?) or wrong (`f` was clearly
meant as a reference, not a call). Ruxen refuses to guess. E0726 fires so the
call site stays explicit: either *call* the function with its required
arguments, or *reference* it under a `Fn` type so auto-call is suppressed.

## Example

A zero-arg function auto-calls cleanly:

```ruxen
def args -> Array[String]
  # ...
end

def main
  let argv = args      # `args` auto-calls -> argv : Array[String]
  if argv.size < 2
    # ...
  end
end
```

An n-arg function cannot auto-call and triggers E0726:

```ruxen
def add(a: Int, b: Int) -> Int
  a + b
end

def main
  let f = add          # ERROR E0726: `add` needs 2 arguments
end
```

## Fix

**Call it** — supply the arguments:

```ruxen
let sum = add(1, 2)
```

**Reference it** — annotate a `Fn` type so the function is referenced without
being called (a `Fn`-typed context suppresses auto-call):

```ruxen
let f: Fn(Int, Int) -> Int = add
let sum = f(1, 2)
```

The same applies when passing a function to a higher-order function: if the
parameter is `Fn`-typed, the reference is passed as a value; otherwise it is
auto-called and its result is passed.
