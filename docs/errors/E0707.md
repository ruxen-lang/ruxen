# E0707: binary operator applied to mismatched numeric types

## Why
Ruxen performs **no implicit numeric coercion** in binary arithmetic
(`+`, `-`, `*`, `/`, `%`). Both operands of an arithmetic operator must
already share the same type. Mixing distinct numeric types — an `Int`
with a `Float`, or an `Int` with an `Int64` — is rejected at type-check.

This matches design principle P5 (*clarity at boundaries*): a widening
or `Int → Float` conversion changes the machine representation of a
value, so Ruxen makes you write it down rather than guessing.

Catching the mismatch here also closes a soundness gap. Before E0707
existed, `a - 3.5` (with `a: Int`) type-checked silently as `Int` and
then crashed later in the compiler with an opaque internal error. A
type error at the source span is far better.

## Example
```rx
def main
  let a: Int = 1
  let b = a - 3.5   # error[E0707]: `Int` and `Float` don't match
end
```

## Fix
Make both operands the same type:

* **Convert explicitly** — `Int#to_f` and `Float#to_i` convert between
  the two:
  ```rx
  let a: Int = 1
  let b = a.to_f - 3.5   # Float - Float
  ```
* **Work in `Float`** — annotate the binding as `Float` so the literal
  is a float and arithmetic stays in floats:
  ```rx
  let a: Float = 1.0
  let b = a - 3.5      # Float - Float
  ```
* **Work in `Int`** — keep both operands integers:
  ```rx
  let a: Int = 1
  let b = a - 4        # Int - Int
  ```

## Notes
- An operand whose type is not yet known, or that already failed with
  another error, does not trip E0707: it is either pinned by a later
  constraint or reported by its own diagnostic.
- Assignment contexts are more permissive: `let x: Float = 42` still
  works through the `Int → Float` literal coercion. E0707
  only governs the operands of arithmetic operators, where unification
  (not coercion) is the rule.
