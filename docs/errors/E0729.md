# E0729: a closure / `Fn` value cannot be formatted into a string (no Display)

## Why

A closure (a `Fn` / `FnMut` / `FnOnce` value) has no `Display`
implementation — there is no meaningful text rendering of a function value.
Interpolating one into a string (`"#{f}"`) or otherwise asking for its `Display`
form is almost always a mistake.

The trap that makes this worth a dedicated diagnostic: in Ruxen a bare
`do … end` is **a block/closure literal, never an expression block** (the same
rule Ruby follows). So this:

```ruxen
let v = do
  let a = 1
  let b = 2
  a + b
end
puts "#{v}"
```

does NOT bind `v` to `3` — it binds `v` to the *un-invoked closure*, and the
interpolation would otherwise print a raw pointer address (silent garbage).
E0729 turns that silent garbage into a clear compile error.

## Example

```ruxen
# error[E0729]: a closure / `Fn` value cannot be formatted into a string
def main
  let v = do
    1 + 2
  end
  puts "#{v}"
end
```

## Fix

If you wanted a *value* computed from several statements, use a helper function
(or an `if`/`match` expression, which DO produce values):

```ruxen
def sum_two -> Int
  let a = 1
  let b = 2
  a + b
end

def main
  let v = sum_two
  puts "#{v}"      # 3
end
```

A `do … end` (or `{ … }`) is a block to **attach to a call** — e.g.
`items.each do |x| … end`, `render do … end`. If you genuinely have a closure
and want to use its *result*, invoke it and interpolate that:

```ruxen
def main
  let f = do
    1 + 2
  end
  puts "#{f.()}"   # 3 — invoke, then format the Int result
end
```

> Design note: if Ruby-style *expression blocks* (a block that is itself a
> value) are ever added to Ruxen, the unambiguous spelling will be `begin … end`
> — `do … end` now firmly means "a block attached to a call". See
> `docs/TASKS.md`.
