# E1702 — `~=` operand type mismatch

The regex-match operator `~=` only accepts a `String` (or `&String` /
`Str`) on the left and a `Regex` on the right.

## Example (rejected)

```ruxen
5 ~= /foo/                  # E1702: lhs is Int
let s = String.from("x")
s ~= "literal"              # E1702: rhs is String, not Regex
```

## Fix

Use a regex literal on the right:

```ruxen
let s = String.from("hello")
if s ~= /hel/
  puts "matched"
end
```

For a runtime-built pattern, use `Regex.new`:

```ruxen
let pat = Regex.new(String.from("hel"), String.from("")).unwrap!
if s ~= pat
  puts "matched"
end
```

## Why a separate operator?

`==` would be ambiguous: comparing a `String` to a `Regex` for
equality is rarely useful, but the surface read of `s == /pat/` looks
indistinguishable from value equality. `~=` carries the "matches?"
semantics explicitly — readable as "tilde-equals", "matches", or
"squiggly equals".
