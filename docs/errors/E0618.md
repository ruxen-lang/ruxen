# E0618: auto-synth PartialOrd: field type does not satisfy PartialOrd

## Why
A synthesized `PartialOrd` provides a lexicographic partial order over
the fields in declaration order. Each field type must be ordered
itself. Primitives, `String` and user types whose fields all qualify
are; an opaque C handle such as `Mutex[Int]` is not.

`PartialOrd` is Rust vocabulary and is [deprecated]. The Ruby form is
`include Comparable` with a `<=>` method.

## Example

A [deprecated] `include PartialOrd` over a C handle field, rejected with E0618:

```ruby
class Pair
  a: Int
  b: Mutex[Int]             # a C handle: not ordered
  include PartialOrd
end
```

## Fix
Include `Comparable` and order on the fields that have an order.

Compiles [implemented]:

```ruby
class Pair
  a: Int
  b: Mutex[Int]
  include Comparable

  def <=>(other: &Pair) -> Int
    @a <=> other.a
  end
end
```
