# E1121: alias forms a cycle

## Why
`alias` flattens to a single canonical target at declaration time, so an alias
chain (`alias a b` where `b` is itself `alias b c` …) must terminate at a real
method. If the chain loops back on itself without reaching a real method, there
is no canonical target to resolve to, and the compiler rejects it rather than
loop forever.

See [docs/decisions/alias-keyword.md](../decisions/alias-keyword.md) (decision D4).

## Example
```rx
class C
  alias a b   # error[E1121]: `a` resolves to no method (a → b → a → …)
  alias b a
end
```

## Fix
Anchor the chain on a real method:

```rx
class C
  def impl -> Int
    1
  end
  alias a impl
  alias b a     # a → impl, b → impl
end
```
