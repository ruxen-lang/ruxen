# E0728: top-level expression statement conflicts with explicit `def main`

## Why

Ruxen normally executes top-level expression statements as a Ruby-style
script. Before name resolution, the compiler hoists declarations and moves the
executable expressions into an implicit `main`, preserving their source order.

If the same program already declares `def main`, there are two possible entry
point bodies: the hand-written function and the loose top-level statements.
Ruxen rejects that ambiguous combination with E0728 rather than silently
choosing or merging one of them.

## Example

```ruxen
puts "loose statement"

def main
  puts "explicit entry"
end
```

## Fix

Move the loose statements into the existing `main`:

```ruxen
def main
  puts "loose statement"
  puts "explicit entry"
end
```

Or remove the explicit function and use script style:

```ruxen
puts "loose statement"
puts "implicit entry"
```

`ruxen test` continues to provide its own explicit runner `main`; test-file
statements are placed inside that runner before the normal compile pipeline.
