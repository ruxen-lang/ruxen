# E0728: top-level expression statement is not executable; wrap it in `def main`

## Why

A Ruxen source file's top level holds *declarations* — `def`, `class`,
`struct`, `enum`, `mixin`, `impl`, `module`, `use`, `const`, `type`, `lib`.
An expression *statement* at module scope (a bare call such as
`Tester.describe("…") do … end`) has nowhere to run: nothing executes a
top-level statement directly.

The **parser accepts** the shape so the shared parser surface — used by the
compiler, the LSP, and `ruxen fmt` — can round-trip test files written as a
bare `Tester.describe(...) do … end` block (and so `ruxen fmt` no longer
errors at `1:1` on them; see issue Q23). But on the **direct compile path**
(`ruxen compile` / `ruxen build` on a raw file) such a statement is rejected
with E0728, because the compiler has no implicit-`main` script mode.

`ruxen test` does NOT hit this: it discovers `tests/**.rx`, **hoists** the
top-level items and **wraps** the remaining statements in a synthesised
`def main` before compiling, so the statements run inside `main`.

## Example

```ruxen
# error[E0728]: top-level expression statement is not executable
Tester.describe("Calculator") do |t: &var Tester|
  t.it("adds") do
    t.expect(1 + 2).to_eq(3)
  end
end
```

## Fix

Wrap the statement(s) in `def main` (the form `ruxen test` synthesises for
you):

```ruxen
use std.test.Tester
use std.test.Runner

def main
  let r = Runner.new("calc")
  Runner.set_current(r.handle_addr)

  Tester.describe("Calculator") do |t: &var Tester|
    t.it("adds") do
      t.expect(1 + 2).to_eq(3)
    end
  end

  r.execute
end
```

Or simply run the file through `ruxen test`, which performs the wrapping
automatically.
