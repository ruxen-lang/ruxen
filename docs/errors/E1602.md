# E1602: published version tag already exists at remote

## Why
`ruxen publish` tags the current package as `v<name>-<version>` and
pushes that tag to the configured git remote. If the same tag is
already present at the remote, the publish must be rejected — git
would otherwise refuse the push, and silently bumping the version
would let the same source land under two distinct tags.

## Example
```
$ ruxen publish
error[E1602]: tag `vmy-pkg-0.1.0` already exists at remote `origin`
  hint: bump the version in Ruxen.toml, then re-run `ruxen publish`
```

## Fix
1. Open `Ruxen.toml` and bump the package version (per semver).
2. Commit the bump.
3. Re-run `ruxen publish`.

If the existing tag is the result of an earlier mistake, delete it
first — but only after confirming no consumer has pinned to it:

```bash
git push origin :refs/tags/vmy-pkg-0.1.0
git tag -d vmy-pkg-0.1.0
```

## Notes
- The tag-existence check uses `git ls-remote --tags` so a stale
  local tag does not mask a missing remote one (or vice versa).
- Companion code: [E1600](E1600.md) — workspace member not found.
