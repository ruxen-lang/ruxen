# E1122: alias name collides with an existing definition

## Why
An alias introduces a NEW name. If that name already names a real method (on the
type) or a real function (in scope), the alias would shadow or duplicate it,
which is ambiguous — so the compiler rejects it. Aliasing a name to itself
(`alias x x`) is the degenerate form of this collision and reports the same code.

See [docs/decisions/alias-keyword.md](../decisions/alias-keyword.md) (decision D5).

## Example
```rx
class C
  def a -> Int
    1
  end
  def b -> Int
    2
  end
  alias a b     # error[E1122]: `a` already names a method on `C`
end
```
```rx
class C
  def a -> Int
    1
  end
  alias a a     # error[E1122]: aliases a name to itself
end
```

## Fix
Choose a new name for the alias that is not already defined:

```rx
class C
  def b -> Int
    2
  end
  alias also_b b
end
```
