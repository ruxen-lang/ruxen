# E0602: Copy implies Clone — a Copy type must also support Clone

## Why
`Copy` is a marker that strengthens `Clone`: every `Copy` type must
also be `Clone`. A type body that says `include Copy` therefore also
needs `include Clone`; the compiler does not add the missing `Clone`
for you, so the pair always reads together.

The check runs on `struct` and `enum` bodies, the only types that can
be `Copy` (a `class` never is, E0603). Both are [deprecated]; their
replacement, `Data.define`, is [planned](../../TODO.md#t-data-define).

## Example

A [deprecated] `struct` that includes `Copy` without `Clone`, rejected with E0602:

```ruby
struct Point
  x: Int
  y: Int
  include Copy    # Copy without Clone
end
```

## Fix
Include `Clone` next to `Copy`.

The [deprecated] `struct` with both markers compiles:

```ruby
struct Point
  x: Int
  y: Int
  include Copy
  include Clone
end
```
