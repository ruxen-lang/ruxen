# E0602: Copy implies Clone — a Copy type must also support Clone

## Why
`Copy` is a marker that strengthens `Clone`: every `Copy` type must
also satisfy `Clone`. Because both are auto-synthesized (§3.6),
this constraint is usually invisible — when every field is `Copy`
it is also `Clone`, so both are synthesized in lockstep.

The diagnostic surfaces when a user-defined `clone` method is
written in a way that breaks the auto-synthesis pairing — for
example, defining a `clone` whose return shape does not match the
synthesized one, or marking the type as `Copy`-eligible while
overriding `clone` with a divergent signature.

## Example
```rvn
struct Point
  x: Int
  y: Int

  def clone -> &Point    # divergent: synth Clone would return Point
    self
  end
end                       # error[E0602]
```

## Fix
Either drop the override (let the auto-synth pair stand) or align
the override with the canonical `Clone` shape:

```rvn
struct Point
  x: Int
  y: Int

  def clone -> Point      # matches the synth shape
    Point.new(self.x, self.y)
  end
end
```
