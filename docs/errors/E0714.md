# E0714: BufReader/BufWriter inner type must be File or TcpStream (v1)

## Why
v1 ships `BufReader[R]` and `BufWriter[W]` parameterised by monomorphisation
over the closed set `{File, TcpStream}`. There is no formal `Read` /
`Write` mixin yet — that lands in v1.5 with the iterator trait work.
The runtime carves a 1-byte `kind` tag into the wrapper spine and
branches on it for every fill / flush; the closed-set check at typeck
keeps that tag honest.

## Example
```rvn
# error[E0714]: BufReader/BufWriter inner type must be File or TcpStream (v1)
let s = "data".to_string()
let br = BufReader.new(s)
```

## Fix
Use a `File` or `TcpStream` as the inner:
```rvn
match File.open(&path)
  Ok(f)  ->
    let br = BufReader.new(f)
    # ...
  Err(_) -> ()
end
```

Or for `with_capacity` (note: `cap` first, `inner` second):
```rvn
let br = BufReader.with_capacity(16384, f)
```

## Notes
- The check fires at typeck on `.new(inner)` and `.with_capacity(cap, inner)`.
  The argument's resolved type is consulted; references (`&File`, `&var
  TcpStream`) are peeled before the match.
- `Ty::Infer` / `Ty::Error` pass through silently so we don't
  double-report when the inner is already a type-error from elsewhere.
- Lifting this restriction is tracked under #06.8 (stdlib self-hosting)
  / v1.5 (iterator + Read/Write trait surface).
