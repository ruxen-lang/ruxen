# E1017: `include` of a type that is not a mixin

## Why
`include` mixes a mixin's methods into a class, struct or enum. The
compiler rejected this `include` because the name it was given is a
class, struct, enum or type alias, not a mixin. Ruby raises
`TypeError (wrong argument type Class (expected Module))` for the same
code.

A common cause is the old spelling `include Hash`: `Hash` is the
collection class, and the mixin that makes a type usable as a `Hash` key
is `Hashable`.

## Example
```rx
class Bar
end

class Foo
  include Bar        # error[E1017]: `Bar` is a class, not a mixin
end

struct Key
  id: Int
  include Hash       # error[E1017]: did you mean `include Hashable`?
end
```

## Fix
Include a mixin, or turn the shared behaviour into one:

```rx
mixin Greeting
  def greeting -> String
    "hi"
  end
end

class Foo
  include Greeting
end

struct Key
  id: Int
  include Hashable
  include Eq
  include PartialEq
end
```

To reuse a class's behaviour, subclass it (`class Foo < Bar`) instead.
