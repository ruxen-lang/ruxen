# E0613: auto-synth PartialEq: field type does not satisfy PartialEq

## Why
A synthesized `PartialEq` provides an `==` that compares fields
pair-wise. Every field must therefore itself support `==`, otherwise
there would be no way to compare it. An opaque C handle such as
`Mutex[Int]` does not.

`include PartialEq` is Rust vocabulary and is [deprecated]; the Ruby
form is a `def ==(other: &Self) -> Bool` method. Value types get a
structural `==` with no include [planned](../../TODO.md#t-d8).

## Example

A [deprecated] `include PartialEq` over a C handle field, rejected with E0613:

```ruby
class Pair
  a: Int
  b: Mutex[Int]             # a C handle: no ==
  include PartialEq
end
```

## Fix
Write `==` by hand and compare only the fields that have a meaning for
equality.

Compiles [implemented]:

```ruby
class Pair
  a: Int
  b: Mutex[Int]

  def ==(other: &Pair) -> Bool
    a == other.a
  end
end
```
