# E0605: cannot synthesize Default on enum without a `default` variant

## Why
Unlike a struct (where `Default` is the field-wise default), an
enum has no canonical zero variant, so `include Default` on an enum
has no value to produce. The compiler reports E0605 for every enum
with at least one variant whose body says `include Default` (an enum
with no variants reports E0616).

A `default` variant directive was planned for this case but does not
parse today, so there is no way to mark one variant as the default.

Both pieces are Rust vocabulary: `enum` is [deprecated] (replaced by
symbols and `Data` variants, [planned](../../TODO.md#t-data-define)),
and so is the `Default` mixin (replaced by arguments with defaults).

## Example

A [deprecated] `enum` that includes `Default`, rejected with E0605:

```ruby
enum Mode
  Read
  Write
  Append
  include Default    # which variant is the default?
end
```

## Fix
Drop `include Default` and name the default where it is needed, for
example as an argument default.

The [deprecated] `enum` with an argument default compiles:

```ruby
enum Mode
  Read
  Write
  Append
end

def open_with(mode: Mode = Mode.Read)
  puts "opened"
end

open_with()
```
