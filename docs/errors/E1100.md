# E1100: captured value across thread boundary is not Send

## Why
A closure passed to `Thread.spawn` must move only `Send`-safe values
across the thread boundary. The compiler walked the closure's
capture list and found a value whose type does not implement
`Send`.

See [docs/specs/ownership/send_sync_enforcement.spec.md](../specs/ownership/send_sync_enforcement.spec.md)
§B6 for the rule.

## Example
```rvn
class Foo
  def init
  end
end

def main
  let f = Foo.new
  let _h = Thread.spawn({ || f })   # E1100: Foo is not Send
end
```

## Fix
User classes are not auto-derived for `Send` in v1. If the class is
genuinely safe to share across threads, add an explicit `include
Send`:

```rvn
class Foo
  include Send
  def init
  end
end
```

For classes wrapping raw pointers or non-Send foreign handles, use
`unsafe include Send` to manually assert safety:

```rvn
class WrapsRawPointer
  unsafe include Send
  def init
  end
end
```

If a capture is held by reference, the closure requires `&T: Send`,
which means `T: Sync`. Either restructure the closure to take ownership
(by-move) or make the type `Sync`.
