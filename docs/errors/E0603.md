# E0603: Copy cannot be auto-synthesized on a class; use a struct

## Why
Ruxen `class`es have reference identity and (potentially) destructors.
`Copy` would silently alias that identity and skip drop, which is
almost never what the author wants. The compiler reserves `Copy` for
plain-old-data value types.

The diagnostic fires when a `class` body says `include Copy`.

The title above is the compiler's message, which still says "use a
struct". `struct` is [deprecated]; this page recommends the Ruby forms
instead: a `class` with `clone`, or `Data.define` for a value type once it
lands ([planned](../../TODO.md#t-data-define)).

## Example

Rejected with E0603 [implemented]:

```ruby
class Counter
  value: Int
  include Copy             # a class cannot be Copy
  include Clone
end
```

## Fix
Drop `include Copy` and duplicate the object explicitly with `clone`.

Compiles [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Counter
  value: Int

  def init(value: Int)
    @value = value
  end
  include Clone
end

a = Counter.new(0)
b = a.clone              # explicit duplicate
puts b.value
```

A value type without identity can be `Copy`. Today that is a
[deprecated] `struct` with `include Copy` and `include Clone` (see
E0602); its replacement, `Data.define`, is
[planned](../../TODO.md#t-data-define).
