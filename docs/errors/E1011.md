# E1011: type does not satisfy Send

## Why
A value that may cross a thread boundary must satisfy `Send`: a
parameter typed `any Send`, a generic parameter bounded by `Send`, or a
capture of a closure handed to another thread. Primitives, `String` and
collections of `Send` values are `Send`. A user class is `Send` only when
its body says `include Send`; the compiler does not infer it from the
fields. A raw pointer is never `Send`.

(A closure handed to `Thread.spawn` reports E1100, `Mutex.new` E1101 and
`SharedSync.new` E1102; E1011 is every other `Send` requirement.)

## Example

Rejected with E1011 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Counter
  n: Int

  def init(n: Int)
    @n = n
  end
end

def send_off(v: any Send)
  puts "sent"
end

send_off(Counter.new(1))   # E1011: Counter does not include Send
```

## Fix
Declare that the class is safe to move to another thread, when every
field is.

Compiles and prints `sent` [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Counter
  n: Int

  def init(n: Int)
    @n = n
  end
  include Send
end

def send_off(v: any Send)
  puts "sent"
end

send_off(Counter.new(1))
```

For shared ownership across threads, wrap the value in `SharedSync`.
