# E0601: cannot synthesize Copy: field has non-Copy type

## Why
`Copy` is a structural marker: a value type is `Copy` only when every
field is itself `Copy`. Heap-owning types such as `String`, `Array`,
and user `class`es are not `Copy`, so a type that contains one of
them cannot itself be `Copy`: bit-copying would alias the heap
ownership.

The diagnostic fires on a `struct` (or `enum`) whose body says
`include Copy` while one of its fields (or variant payloads) is not
`Copy`, and names the offending field. A `class` never takes `Copy`
(E0603).

`struct` and `enum` are [deprecated]; their replacements are
`Data.define` [planned](../../TODO.md#t-data-define) and `Struct.new`
[planned](../../TODO.md#t-struct-new). Copy for a `Data` value whose
fields are all Copy is part of the `Data.define` item.

## Example

A [deprecated] `struct` with a `String` field and `include Copy`, rejected with E0601:

```ruby
struct Person
  name: String     # String is not Copy
  age: Int
  include Copy
  include Clone
end
```

## Fix
Keep only `Copy` fields in a `Copy` type, or drop `include Copy` and
use a `class`, calling `clone` when you need a duplicate.

A [deprecated] `struct` whose fields are all `Copy` compiles:

```ruby
struct PersonId
  id: Int          # all fields Copy, so the struct can be Copy
  age: Int
  include Copy
  include Clone
end
```

A class that owns heap data and is cloned explicitly compiles [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Person
  name: String
  age: Int

  def init(name: String, age: Int)
    @name = name
    @age = age
  end
  include Clone
end

a = Person.new("Alice", 30)
b = a.clone
puts a.name
puts b.name
```
