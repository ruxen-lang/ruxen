# E0601: cannot derive Copy: field has non-Copy type

## Why
`derive Copy` requires that every field of the type already
implements `Copy`. Heap-owning types such as `String`, `Vec`, and
user `class`es are not `Copy`, so a struct that contains one of
them cannot itself be `Copy` — bit-copying would alias the heap
ownership.

## Example
```rvn
@[derive(Copy, Clone)]
struct Person
  name: String
  age: Int
end
```

## Fix
Either drop `Copy` and rely on `Clone` for an explicit duplicate,
or replace the offending field with a `Copy` type:

```rvn
@[derive(Clone)]
struct Person
  name: String
  age: Int
end
```
