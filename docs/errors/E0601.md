# E0601: cannot synthesize Copy: field has non-Copy type

## Why
`Copy` is a structural marker: a `struct` is `Copy` only when every
field is itself `Copy`. Heap-owning types such as `String`, `Array`,
and user `class`es are not `Copy`, so a struct that contains one of
them cannot itself be `Copy` — bit-copying would alias the heap
ownership.

The compiler auto-synthesizes `Copy` for any `struct` whose fields
all qualify. The user does not opt in with a directive; they opt
out by introducing a non-`Copy` field. This diagnostic fires at
the use site (when the value is copied implicitly) and names the
offending field.

## Example
```rvn
struct Person
  name: String     # String is not Copy
  age: Int
end

def main
  let p = Person.new("Alice", 30)
  let q = p        # error[E0601]: Person is not Copy
  puts p.name      # because the `name` field's String is not Copy
end
```

## Fix
Either accept move semantics (use the value once, or `clone` it
explicitly), or replace the offending field with a `Copy` type:

```rvn
struct PersonId
  id: Int          # all fields Copy → struct is Copy
  age: Int
end
```

For types that genuinely own heap, define `clone` and call it
explicitly when you need a duplicate.
