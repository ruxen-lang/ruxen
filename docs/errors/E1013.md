# E1013: non-`static` value captured by send-required closure

## Why
A closure handed to a parameter that requires `Send` (typed
`any Fn[...] + Send`, the shape a thread spawn takes) may outlive the function that
created it, which the compiler models as a `static` lifetime bound. So
the closure may not borrow the caller's stack.

A block `{ ... }` borrows its captures, so a block that captures a
non-Copy local is rejected. A lambda `-> { }`, a `proc { }` and a `move`
closure own their captures, so they are fine, except when the capture is
itself a reference: owning `&T` does not own what it points to, which
still lives in the caller's frame.

## Example

A parameter typed `any Fn[...] + Send` requires a send-safe closure.
A lambda that captures a reference is rejected with E1013 [implemented]:

```ruby
def go(f: any Fn[() -> Int] + Send) -> Int
  f.call
end

s = "hi"
r = &s
puts go(-> { r.size })   # E1013: the lambda owns `r`, not `s`
```

The same lambda passed to `Thread.spawn` is not rejected today: the
check fires only for a parameter whose type says `+ Send`, and
`Thread.spawn(-> { r.size })` compiles and runs. That is a
[known issue](../../TODO.md#t-d16).

## Fix
Capture the value itself, so the closure owns it (the value moves into
the closure and cannot be used afterwards), or capture a `clone`.

Compiles and prints `2` [implemented]:

```ruby
def go(f: any Fn[() -> Int] + Send) -> Int
  f.call
end

s = "hi"
puts go(-> { s.size })
```
