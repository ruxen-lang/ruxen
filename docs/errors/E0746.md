# E0746: a generic instantiation grows without end

## Why

Ruxen compiles a generic body once per concrete type it is used with. A
body that uses itself with a larger type than it was given (`Nest[T]`
building a `Nest[Array[T]]`) asks for `Nest[Int]`, then
`Nest[Array[Int]]`, then `Nest[Array[Array[Int]]]`, with no end. The
compiler stops when a type argument holds more than 256 type nodes
(the type and every type nested in it). Counting size rather than depth
also stops a type that grows in width: `Nest[T]` building
`Nest[(T, T)]` doubles on every step and is rejected within a few steps.
This is polymorphic recursion, which Ruxen does not support.

The error names the template and where it is declared. For a template
declared in the standard library the location also names its package:
`(at 50:3 in the standard library package `map`)`.

## Example

Rejected with E0746 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Nest[T]
  v: T

  def init(v: T)
    @v = v
  end

  def deeper -> Int
    # error[E0746]: `Nest` instantiates itself with an ever larger type: the
    # instantiation `Nest[Array[Array[...]]]` holds more than 256 type nodes
    Nest.new([@v]).deeper
  end
end

puts(Nest.new(1).deeper)
```

Rejected with E0746 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Nest[T]
  v: T

  def init(v: T)
    @v = v
  end

  # error[E0746]: `Nest[(T, T)]` doubles on every step
  def deeper -> Nest[(T, T)] where T: Clone
    Nest.new((@v.clone, @v.clone))
  end
end
```

## Fix

Keep the recursion on the same type, or stop it with a type that does not
grow: store the nested values in a field of a fixed type (`Array[T]`)
instead of a new instantiation per level.
