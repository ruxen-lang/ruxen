# E0703: const expression overflows or divides by zero during evaluation

## Why
Const expressions in array-size slots (`[T; ...]`) fold to a single
`UInt64` at resolve time.  When a pure-literal sub-tree overflows
(`+ - *` wraps past the `UInt64` maximum, `-` borrows below zero) or
divides by zero (`_ / 0`), the compiler cannot produce a sound layout
for the corresponding type, and emits this code.

The check runs after constant folding. Successful pure-literal
arithmetic folds into a single value, so any literal-only arithmetic
left unfolded is by construction an evaluation failure. Expressions
that reference an in-scope const param (`N + 1`, `M * 2`) defer the
check to monomorphization — overflow at that point depends on the
instantiation, not the source.

A literal larger than the `Int` maximum is rejected by the lexer
first (E0004). In a const-generic argument (`Vector[Int, a + b]`) an
overflowing sum wraps to a negative value today and is reported as
E0701 instead of E0703.

## Example: overflow

Rejected with E0703 [implemented]:

```ruby
class Buf
  data: [Int; 4294967296 * 4294967296]   # 2**64: past UInt64 max
end
```

## Example: division by zero

Rejected with E0703 [implemented]:

```ruby
class Bad
  data: [Int; 10 / 0]   # error[E0703]
end
```

## Example: borrow below zero

Rejected with E0703 [implemented]:

```ruby
class Bad
  data: [Int; 0 - 1]    # UInt64 has no negatives
end
```

## Fix
Choose const arguments whose folded value fits in `UInt64` and whose
divisors are non-zero.

Compiles [implemented]:

```ruby
class Buf
  data: [Int; 4096 * 4]
end
```

## Notes
- Spec §B8 reserves one E0703 slot for both `E-CONST-OVERFLOW` and
  `E-CONST-DIV-ZERO`.  The diagnostic message distinguishes them:
  *"const expression overflows during evaluation"* vs.
  *"const expression divides by zero"*.  v2 polish: structured
  sub-kind on the diagnostic so tooling can branch without
  string-matching.
- `UInt64` has no negatives, so `0 - 1` surfaces as the overflow
  variant rather than a separate "underflow" code.
- Param-bearing trees (`N + 1`, `M * 2`) are *not* flagged here
  even if they would overflow for some `N` — overflow at
  monomorphization is the v2 deliverable that needs the
  per-instantiation binding-threading prep work tracked in the
  const-generics spec's "S7 follow-up" section.
