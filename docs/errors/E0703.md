# E0703: const expression overflows or divides by zero during evaluation

## Why
Const expressions in const-generic argument positions and array-size
slots fold to a single `u64` at resolve time.  When a pure-literal
sub-tree overflows (`+ - *` wraps past `u64::MAX`, `-` borrows below
zero) or divides by zero (`_ / 0`), the compiler cannot produce a
sound layout for the corresponding type instantiation, and emits
this code.

The check runs after the S8.S4 normal-form rewriter
(`ConstExpr::normal_form`).  Successful pure-literal arithmetic
constant-folds into a single `Lit`; surviving `Op` nodes with
literal children are by construction the eval-failure cases.  Trees
that reference an in-scope const param (`N + 1`, `M * 2`) defer the
check to monomorphization — overflow at that point depends on the
instantiation, not the source.

## Example: overflow
```rvn
struct Buf
  data: [Int; 18446744073709551615 + 1]   # u64::MAX + 1
end                                       # error[E0703]
```

## Example: division by zero
```rvn
struct Bad
  data: [Int; 10 / 0]   # error[E0703]
end
```

## Example: nested overflow inside a multiplication
```rvn
class Vector[T, const N: USize]
  data: USize
  def init(@data: USize); end
end

def f(v: Vector[Int, 9223372036854775807 + 9223372036854775807])
end                                       # error[E0703]
```

## Fix
Choose const arguments whose folded value fits in `u64` and whose
divisors are non-zero.  When the maximum sensible value of a
parameter is small, tighten the surrounding const-`USize` bound via
a `where N < 1024` predicate once §B9 (S9 work) lands.

## Notes
- Spec §B8 reserves one E0703 slot for both `E-CONST-OVERFLOW` and
  `E-CONST-DIV-ZERO`.  The diagnostic message distinguishes them:
  *"const expression overflows during evaluation"* vs.
  *"const expression divides by zero"*.  v2 polish: structured
  sub-kind on the diagnostic so tooling can branch without
  string-matching.
- `u64` has no negatives, so `0 - 1` surfaces as the overflow
  variant rather than a separate "underflow" code.
- Param-bearing trees (`N + 1`, `M * 2`) are *not* flagged here
  even if they would overflow for some `N` — overflow at
  monomorphization is the v2 deliverable that needs the
  per-instantiation binding-threading prep work tracked in the
  const-generics spec's "S7 follow-up" section.
