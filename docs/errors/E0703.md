# E0703: const-arg expression overflows during evaluation (reserved)

**Status:** reserved by `docs/specs/types/const-generics.spec.md`
§"Error code reservations".  No emit site today.  S8.S1 ships the
underlying evaluator support (`ConstEvalError::Overflow` and
`ConstEvalError::DivisionByZero` — see commit c0ea652); a follow-up
will surface those evaluator errors as diagnostics with this code at
the monomorphization site.

## Why (planned)

Const expressions in const-generic argument positions and array-size
slots fold to a single `u64` at monomorphization.  When the fold
overflows (`+ - *` wraps past `u64::MAX`, `-` borrows below zero) or
divides by zero (`_ / 0`), the compiler cannot produce a sound layout
for the corresponding type instantiation, and emits this code.

## Example (planned)

```rvn
struct Buf[const N: USize]
  data: [Int; N * 10]
end

def main
  # USize is u64; 0xFFFF_FFFF_FFFF_FFFF * 10 overflows.
  let _b = Buf[Int, 0xFFFF_FFFF_FFFF_FFFF].new   # error[E0703]: overflow
end
```

```rvn
struct DivZero[const N: USize]
  data: [Int; 10 / N]
end

def main
  let _d = DivZero[Int, 0].new   # error[E0703]: division by zero
end
```

## Fix (planned)

Choose const arguments whose folded value fits in `u64` and produces
a non-zero divisor.  When the maximum sensible value of a parameter
is small (e.g. `N < 1024`), tighten the surrounding const-`USize`
bound via a `where N < 1024` predicate once §B9 (S9 work) lands.

## Notes

- The spec's §B8 diagnostic table lists `E-CONST-OVERFLOW` and
  `E-CONST-DIV-ZERO` as separate human-readable labels; both surface
  through this single E0703 slot in v1.  Splitting (or attaching
  a structured sub-kind to the diagnostic) is a v2 polish item.
- Evaluator helper: `ConstExpr::eval` already returns
  `Err(ConstEvalError::Overflow)` and `Err(ConstEvalError::DivisionByZero)`;
  the monomorphization-side wiring maps both into this code with the
  problematic span when it lands.
