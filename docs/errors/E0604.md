# E0604: Eq implies PartialEq — a type must satisfy both together

## Why
`Eq` is the total-equality refinement of `PartialEq`. Every `Eq`
type must also satisfy `PartialEq`, because `==` is defined on
`PartialEq`. Because both are auto-synthesized (§3.6) when every
field qualifies, this constraint is usually invisible.

The diagnostic surfaces when a user override breaks the lockstep —
for example, defining a custom `==` (PartialEq) that is not total,
on a type whose fields would otherwise qualify it for `Eq`. The
compiler refuses to silently demote the `Eq` synthesis.

## Example
```rvn
struct Id
  value: Int

  def ==(other: &Id) -> Bool      # custom partial equality
    if self.value == 0; return false; end
    self.value == other.value
  end
end                                # error[E0604]: Eq required total
```

## Fix
Either drop the custom `==` (let auto-synth supply total equality)
or accept that the type is only `PartialEq` and update use sites
accordingly:

```rvn
struct Id
  value: Int            # auto-synth: PartialEq + Eq, both total
end
```
