# E0604: Eq implies PartialEq — a type must satisfy both together

## Why
`Eq` is the total-equality refinement of `PartialEq`, and `==` is
defined on `PartialEq`. A type body that says `include Eq` therefore
also needs `include PartialEq`; the compiler does not add the missing
one for you.

Both mixins are Rust vocabulary and are [deprecated]. The Ruby form is
a `def ==(other: &Self) -> Bool` method on the type. Value types get a
structural `==` with no include at all
[planned](../../TODO.md#t-d8).

## Example

A [deprecated] `include Eq` without `include PartialEq`, rejected with E0604:

```ruby
class Id
  value: Int
  include Eq        # Eq without PartialEq
end
```

## Fix
Define `==` on the type, the Ruby form (or, in the [deprecated] form,
include `PartialEq` next to `Eq`).

Compiles [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class Id
  value: Int

  def init(value: Int)
    @value = value
  end

  def ==(other: &Id) -> Bool
    @value == other.value
  end
end

puts Id.new(1) == Id.new(1)
```
