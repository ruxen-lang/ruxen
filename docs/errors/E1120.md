# E1120: alias target not found

## Why
A Ruby-style `alias new_name old_name` introduces `new_name` as a second name
for an existing method or free function. If `old_name` does not name anything
visible in the alias's scope, there is nothing to alias and the compiler
rejects it.

For a method alias, the target is sought among the enclosing type's methods
(its own `def`s, its `lib`-block FFI methods, and the methods it gains by
`include`-ing a mixin). For a free-function alias, the target is sought among
the callable functions visible at that scope.

See [docs/decisions/alias-keyword.md](../decisions/alias-keyword.md) (decision D5).

## Example
```rx
class C
  def area -> Int
    1
  end
  alias surface perimiter   # error[E1120]: `perimiter` is not a method on `C`
end
```

## Fix
Point the alias at a name that exists (mind the spelling):

```rx
class C
  def area -> Int
    1
  end
  alias surface area
end
```

## Notes
- Aliasing a method a type gets ONLY from a mixin **default body** (not a method
  the type itself defines) is a staged Tier-1 limitation and also reports E1120.
  Define the method on the type, or alias a method the type owns.
