# E1123: operator aliases are not yet supported

## Why
`alias` in Tier 1 supports plain method/function names, including `?`/`!` names
(`alias member? include?`, `alias add! push`). Operator-symbol names
(`alias << push`, `alias [] get`) route through a separate operator-desugar
lowering path than ordinary method-name mangling, so wiring them as aliases is
staged for Tier 2. Rather than half-wire it (which would miscompile), the
compiler rejects an operator-spelled alias new-name or target with a clear,
actionable error.

See [docs/decisions/alias-keyword.md](../decisions/alias-keyword.md) (decision D6).

## Example
```rx
class V
  def push(x: Int) -> Int
    x
  end
  alias << push     # error[E1123]: operator aliases are staged for Tier 2
end
```

## Fix
Define the operator method directly (operators ARE methods in Ruxen), or use a
plain-name alias:

```rx
class V
  def push(x: Int) -> Int
    x
  end
  def <<(x: Int) -> Int    # define the operator method itself
    self.push(x)
  end
  alias append push        # …or a plain-name synonym
end
```

## Notes
- `?` and `!` are NOT operators — the lexer absorbs them into the identifier, so
  `alias member? include?` and `alias save! commit` work in Tier 1.
