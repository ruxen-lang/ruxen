# E1123: operator alias has no supported expression dispatch path

## Why
Operator aliases are valid when Ruxen has an expression form that dispatches to
that operator method. Binary `+ - * / % & | ^ << >>`, unary `!`/`-@`, and index
`[]`/`[]=` are supported. Unary `+@` has no surface expression, so accepting it
as an alias would create an unreachable synonym. The compiler rejects that form
instead of silently recording a name no expression can use.

See [docs/decisions/alias-keyword.md](../decisions/alias-keyword.md) (decision D6).

## Example
```rx
class V
  def value -> Int
    1
  end
  alias +@ value     # error[E1123]: unary `+@` has no expression dispatch
end
```

## Fix
Use an operator with a surface dispatch path, or use a plain-name alias:

```rx
class V
  def push(x: Int) -> Int
    x
  end
  alias << push
  alias append push
end
```

## Notes
- `?` and `!` are NOT operators — the lexer absorbs them into the identifier, so
  `alias member? include?` and `alias save! commit` work in Tier 1.
- Comparison/equality/logical/regex names are outside the operator-method grammar
  today and fail parsing rather than reaching E1123.
