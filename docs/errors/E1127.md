# E1127: `super` outside the `init` of a subclass

## Why
`super(...)` calls the parent class's constructor with the given arguments,
on the object being built. Today it only has a meaning inside the instance
`init` of a class that declares a parent (`class Child < Parent`). `def init`
is [deprecated] (the Ruby constructor `def initialize` is
[planned](../../TODO.md#t-initialize)), and `super` from any other method,
reaching the parent's method of the same name, is
[planned](../../TODO.md#t-super).

The compiler used to accept `super` anywhere and compile it to nothing, so the
call was silently skipped. It is now an error.

## Example

Rejected with E1127 [implemented]:

```ruby
def helper -> nil
  super()         # error[E1127]: not inside an `init`
end
```

A [deprecated] `def init` in a class with no parent, rejected with E1127:

```ruby
class Point
  def init(x: Int)
    super(x)      # error[E1127]: `Point` has no parent class
  end
end
```

## Fix
- Give the class a parent (`class Point < Base`) if it should run the parent's
  constructor, or remove the `super` call.
- Call the parent's behaviour from other methods by name until `super` there
  lands.
