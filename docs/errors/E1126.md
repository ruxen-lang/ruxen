# E1126: unknown macro

## Why
`name!(...)` is a **macro** call only when `name` is one of the compiler's own
built-in macros. That set is closed:

| Macro | Status |
|---|---|
| `panic!` | live — stops the program with the given message |
| `array!` / `vec!` / `map!` / `hash!` / `set!` | retired by `ruby-naming.spec.md` §3 (Literals) in favour of the literal forms; kept registered so the old spellings still get a migration message |

Everything else that ends in `!` is an ordinary Ruby bang **name** — `save!`,
`sort!`, `exit!`, `update!` — and is resolved as a normal function or method
call. An undefined one is an `undefined function` error, not a macro.

This code exists to close a silent-miscompile hole. The compiler used to
treat *every* identifier ending in `!` as a macro call, and an unknown macro
produced no code at all. The result was that

```rx
def shout!(x: Int)
  puts "shouting #{x}"
end

def main
  shout!(5)     # compiled clean, printed nothing, fell through
end
```

compiled without a single diagnostic and did nothing — and a `!` function used
for its value (`let r = twice!(3)`) silently produced `0`. A call that cannot
be lowered must now be a hard error, never a no-op.

## Example
```rx
def main
  check!(1 == 1)   # error: undefined function `check!` (not E1126)
end
```

In practice you will not see E1126 from ordinary source: a `name!` whose name
is not a registered macro is parsed as a plain call, so an undefined one
surfaces as `undefined function`, as above. E1126 fires only when a name is registered
as a built-in macro but the compiler has no code for it, that is, when the
compiler would otherwise delete the call.

## Fix
- **Calling a Ruby bang method or function?** Define it. `def save!`,
  `def exit!`, `def shout!(x: Int)` all work and are called with the `!`
  attached: `shout!(5)`, `obj.save!`.
- **Using a retired collection macro?** Use the literal form:
  `[a, b, c]` for `array!` / `vec!`, `{ k => v }` for `map!` / `hash!`,
  `[...].to_set` for `set!`.
- **Seeing it on any other name?** That is a compiler bug (a macro registered
  without an implementation); please report it.

## Notes
- Registering a name as a macro **reserves** that spelling: once `foo` is a
  macro, a user function named `foo!` can no longer be called. That is why the
  list stays minimal.
- The trailing `?` convention (`valid?`, `empty?`) has never gone through the
  macro path; only `!` did.
