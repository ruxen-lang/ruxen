# E1126: unknown macro

## Why
`name!(...)` is a **macro** call only when `name` is one of the compiler's own
built-in macros. That set is closed:

| Macro | Status |
|---|---|
| `panic!` | [deprecated]: stops the program with the given message; replaced by `raise "msg"` ([planned](../../TODO.md#t-exceptions)) or `abort "msg"` |
| `array!` / `vec!` / `map!` / `hash!` / `set!` | [retired] by `ruby-naming.spec.md` §3 (Literals) in favour of the literal forms; kept registered so the old spellings are rejected with E1126 and a migration message |

Everything else that ends in `!` is an ordinary Ruby bang **name** — `save!`,
`sort!`, `exit!`, `update!` — and is resolved as a normal function or method
call. An undefined one is an `undefined function` error, not a macro.

This code exists to close a silent-miscompile hole. The compiler used to
treat *every* identifier ending in `!` as a macro call, and an unknown macro
produced no code at all: a call to a user-defined `shout!(5)` compiled
without a single diagnostic and did nothing, and a `!` function used for its
value (`r = twice!(3)`) silently produced `0`. A call that cannot be lowered
must now be a hard error, never a no-op.

Today a bang method is an ordinary call, which compiles and prints
`shouting 5` [implemented]:

```ruby
def shout!(x: Int)
  puts "shouting #{x}"
end

shout!(5)
```

## Example

Rejected with E0735 [implemented]:

```ruby
check!(1 == 1)   # error[E0735]: undefined function `check!` (not E1126)
```

A `name!` whose name is not a registered macro is parsed as a plain call, so
an undefined one surfaces as `undefined function`, as above. E1126 fires for a
retired collection macro.

`vec!` is a retired Rust form, rejected with E1126 [retired]:

```ruby
xs = vec!(1, 2)   # error[E1126]: macro `vec!` is retired: use the literal form
```

It also fires when a name is registered as a built-in macro but the compiler
has no code for it, that is, when the compiler would otherwise delete the call.

## Fix
- **Calling a Ruby bang method or function?** Define it. `def save!`,
  `def exit!`, `def shout!(x: Int)` all work and are called with the `!`
  attached: `shout!(5)`, `obj.save!`.
- **Using a retired collection macro?** Use the literal form:
  `[a, b, c]` for `array!` / `vec!`, `{ k => v }` for `map!` / `hash!`,
  `[...].to_set` for `set!`.
- **Seeing it on any other name?** That is a compiler bug (a macro registered
  without an implementation); please report it.

## Notes
- Registering a name as a macro **reserves** that spelling: once `foo` is a
  macro, a user function named `foo!` can no longer be called. That is why the
  list stays minimal.
- The trailing `?` convention (`valid?`, `empty?`) has never gone through the
  macro path; only `!` did.
