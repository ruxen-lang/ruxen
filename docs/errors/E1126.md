# E1126: unknown macro

## Why
`name!(...)` is a **macro** call only when `name` is one of the compiler's own
built-in macros. That set is closed and lives in one place,
`compiler/ruxen_core/src/parser/macros.rs`:

| Macro | Status |
|---|---|
| `panic!` | live — lowers to `ruxen_panic(msg)` and an unreachable terminator |
| `array!` / `vec!` / `map!` / `hash!` / `set!` | retired by `ruby-naming.spec.md` §10a in favour of the literal forms; kept registered so the old spellings still get a migration message |

Everything else that ends in `!` is an ordinary Ruby bang **name** — `save!`,
`sort!`, `exit!`, `update!` — and is resolved as a normal function or method
call. An undefined one is an `undefined function` error, not a macro.

This code exists to close a silent-miscompile hole (B87). The parser used to
treat *every* identifier ending in `!` as a macro call, and MIR's macro
lowering ended in a catch-all that produced no code at all. The result was that

```rx
def shout!(x: Int)
  puts "shouting #{x}"
end

def main
  shout!(5)     # compiled clean, printed nothing, fell through
end
```

compiled without a single diagnostic and did nothing — and a `!` function used
for its value (`let r = twice!(3)`) silently produced `0`. A call that cannot
be lowered must now be a hard error, never a no-op.

## Example
```rx
def main
  assert!(1 == 1)   # error[E1126]: unknown macro `assert!`
end
```

In practice you will not see this from ordinary source: a `name!` whose name is
not a registered macro is parsed as a plain call, so an unknown one surfaces as
`undefined function \`assert!\``. E1126 fires when a name has been added to
`BUILTIN_MACRO_NAMES` without a matching lowering arm in
`mir::lower::expr::misc` — that is, when the compiler would otherwise delete
the call.

## Fix
- **Calling a Ruby bang method or function?** Define it. `def save!`,
  `def exit!`, `def shout!(x: Int)` all work and are called with the `!`
  attached: `shout!(5)`, `obj.save!`.
- **Using a retired collection macro?** Use the literal form:
  `[a, b, c]` for `array!` / `vec!`, `{ k => v }` for `map!` / `hash!`,
  `Set.from_iter([...])` for `set!`.
- **Adding a new compiler macro?** Register the name in
  `parser::macros::BUILTIN_MACRO_NAMES` *and* give it a lowering arm in
  `mir::lower::expr::misc`. Registering without lowering is what this error
  reports.

## Notes
- Registering a name as a macro **reserves** that spelling: once `foo` is a
  macro, a user function named `foo!` can no longer be called. Keep the list
  minimal.
- The trailing `?` convention (`valid?`, `empty?`) has never gone through the
  macro path; only `!` did.
