# E1002: cannot borrow as mutable — already borrowed as immutable

## Why
Ruxen enforces "either many readers or one writer". A view of a place
(`x = u.name` reads the field as a borrow) is still live in the
current region, so the compiler refuses a mutable borrow (`&var u.name`,
or a `def var` method call on `u`) that could replace the place while
the view still points into it.

A mutable borrow of an object, an Array or a Hash is its handle, so a
read through a shared borrow of the same object after a write sees the
new contents; that alone is not an error (see E1003). What is rejected is
a write that could leave a live view dangling.

## Example

Rejected with E1002 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class User
  name: String

  def init(name: String)
    @name = name
  end
end

def replace(s: &var String) -> nil
  s = "replaced"
end

u = User.new("ann")
x = u.name             # a view of u.name, used below
replace(&var u.name)   # E1002: replaces u.name while x still views it
puts x
```

## Fix
Finish with the view before taking the mutable borrow, or clone the
value so the view owns a copy.

Compiles and prints `ann` then `replaced` [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class User
  name: String

  def init(name: String)
    @name = name
  end
end

def replace(s: &var String) -> nil
  s = "replaced"
end

u = User.new("ann")
x = u.name
puts x                 # last use of the view
replace(&var u.name)
puts u.name
```

## `&var` arguments
A `&var` argument (explicit `&var u.name`, or a place passed to a `&var`
parameter) is a mutable borrow for the whole call. It conflicts with any
other argument of the same call that views or mutably borrows the same
storage, since the callee could replace the place while it reads the
other argument.

Rejected with E1002 [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class User
  name: String

  def init(name: String)
    @name = name
  end
end

def show_after(s: &var String, w: &String) -> nil
  s = "new"
  puts w                 # w may view the string `s` just replaced
end

u = User.new("ann")
show_after(&var u.name, u.name)   # E1002: both arguments reach `u.name`
```

The object's handle beside a `&var` of one of its fields is fine: the
callee reads the field after the write and sees the new value. Two
`&var` arguments on different roots are fine too.

Compiles and prints `new` [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class User
  name: String

  def init(name: String)
    @name = name
  end
end

def show_owner(s: &var String, w: &User) -> nil
  s = "new"
  puts w.name
end

u = User.new("ann")
show_owner(&var u.name, &u)
```
