# E1002: cannot borrow as mutable — already borrowed as immutable

## Why
Ruxen enforces "either many readers or one writer". An immutable
borrow (`&x`) is already live in the current region, so the
compiler refuses to grant a mutable borrow (`&var x`) that would
let one alias write while the others read.

## Example
```rx
def main
  var v: Array[Int] = Array.new
  v.push(1)
  let r = &v          # immutable borrow live below
  v.push(2)           # E1002: needs &var v while &v is live
  puts "#{r.size}"
end
```

## Fix
Let the immutable borrow end (drop it, or limit its scope) before
taking the mutable borrow:

```rx
def main
  var v: Array[Int] = Array.new
  v.push(1)
  do
    let r = &v
    puts "#{r.size}"
  end
  v.push(2)
end
```

## `&var` arguments and `var self` calls
A `&var` argument (explicit `&var u.name`, or a place passed to a `&var`
parameter) and a `var self` receiver are mutable borrows too. They conflict
with a live borrow of the place (`x = u.name` used later), and, for the
whole call, with the receiver or any other argument that reaches the same
storage: the callee could read or free it while it replaces the place.

```rx
class User
  name: String
  def init(@name: String)
  end

  def rename(s: &var String) -> nil
    s = "new"
    puts @name     # reads the field `s` is replacing
  end
end

def swap_in(s: &var String, u: &User) -> nil
  s = "new"
  puts u.name
end

u = User.new("ann")
u.rename(&var u.name)   # E1002: the receiver `u` reaches `u.name`
swap_in(u.name, u)      # E1002: the second argument reaches it too
```

Pass a separate variable and store it back afterwards, or let the method
change its own field. Two `&var` arguments on different fields of one
object (`swap(&var u.first, &var u.last)`) are fine.
