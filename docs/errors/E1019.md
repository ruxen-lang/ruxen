# E1019: cannot move a borrowed capture out of a closure body

## Why
A closure body **borrows** the variables its closure captures, whatever the
kind:

- a block (a trailing `{ |x| ... }` / `do |x| ... end` bound to a `Fn[...]`
  parameter) borrows them from the scope that declared them, which frees them
  when it ends, however many blocks read them;
- a proc or lambda owns its captures and frees them when the closure is
  dropped; its body runs once per call, so it may only borrow them.

A closure body may therefore read a capture, call `&self` methods on it, pass
it to a `&T` parameter or forward it to a `Fn[...]` parameter, but it may not
use it **by value**:

- return it as the body's value, or cast it (`s as String`);
- bind it (`let q = s`), assign it (`@field = s`), or bind it in a pattern
  (`match s` / `if let Some(v) = o`);
- use it as a multi-assign value (`q, n = s, 1`);
- pass it to a by-value parameter (`eat(s)` with `def eat(s: String)`) or call
  a `consume self` method on it;
- push or store it (`arr.push(s)`, `[s]`, `(s, 1)`, `Some(s)`, `{ "k" => s }`);
- capture it in an owning proc or lambda (`-> { puts(s) }`), stored or not.

Each of those would hand the value to a new owner while its owner still frees
it: a use after free or a double free. For a lambda called twice, the second
call would hand out a value the first call already gave away.

A closure nested in another closure follows the same rule: an owning proc or
lambda nested in a closure body may not capture that body's captures; clone
into a local first.

## Example
```rx
def run(f: Fn() -> nil) -> nil
  f.()
end

def main
  let s = "hello"
  var held: Array[String] = Array.new
  run do
    held.push(s)   # E1019: `s` is borrowed by the block
  end
  puts(s)
end
```

## Fix
Use `.clone` to hand over an owned copy, and keep the original where it is:

```rx
def main
  let s = "hello"
  var held: Array[String] = Array.new
  run do
    held.push(s.clone)
  end
  puts(s)
end
```

To capture the value in a stored proc or lambda from inside a block or
another lambda, clone it into a local first; the proc then owns the clone:

```rx
run do
  let mine = s.clone
  handlers.push(-> { puts(mine) })
end
```

A lambda that hands its own capture to a by-value parameter clones it on each
call:

```rx
let s = "hello"
let f = -> { eat(s.clone) }
f.()
f.()
```

For a shared handle such as quiver's `State` or a `SharedSync`, `.clone` is a
reference-count bump, not a deep copy.
