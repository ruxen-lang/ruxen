# E0743: argument is not a closure matching the parameter's signature

## Why

A parameter typed as a closure (`Fn(Int) -> nil`, `&block: Fn[(Int) -> nil]`,
`Proc[(Int) -> nil]`) is called with the arguments its signature declares. The
argument passed for it must therefore be a block, a lambda or a proc whose
parameters take those types. A value that is not callable at all (an `Int`, a
`String`), or a closure declared with different parameter types, cannot be
called that way.

## Example

```rx
def run(f: Fn(Int) -> nil)
  f.(1)
end

def main
  run(5)
  # error[E0743]: `run` expects a closure `Fn(Int) -> nil` here, found `Int`
  [1, 2].each(->(s: String) { puts(s) })
  # error[E0743]: `each` expects a closure `Fn(Int) -> nil` here, found `Fn(String) -> nil`
end
```

A block or a proc may take FEWER parameters than the signature declares, as in
Ruby: `run do puts("y") end` is fine for `Fn(Int) -> nil`, and the extra
arguments are dropped. A lambda (`->(x) { }`, `lambda { }`) and a closure value
keep exact arity, and no closure may take more parameters than declared.

## Fix

Pass a block or a lambda that takes the declared parameter types. A block's
unannotated parameters take them from the signature.

```rx
def run(f: Fn(Int) -> nil)
  f.(1)
end

def main
  run { |n| puts(n) }
  [1, 2].each(->(n: Int) { puts(n) })
end
```
