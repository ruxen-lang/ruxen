# E1115: `.await` inside `while` / `for` body not yet supported

## Why
Each `.await` becomes a suspension point in the lowered state
machine. A `.await` in straight-line code generates a single new
state; a `.await` inside the body of a loop would need one state
per iteration plus a re-entry edge back to the loop head. v1 does
not yet implement loop-aware state-machine lowering, so the
compiler rejects the construct rather than miscompile it.

## Example

Rejected with E1115 [implemented]:

```ruby
class Source
  left: Int

  def has_more -> Bool
    @left > 0
  end
end

async def next_chunk(s: &Source) -> Int
  1
end

async def drain(source: &Source) -> Int
  total = 0
  while source.has_more
    chunk = next_chunk(source).await       # error[E1115]
    total = total + chunk
  end
  total
end
```

## Fix
Until loop-aware lowering lands, restructure the loop into a recursive
`async def`.

Compiles [implemented]:

```ruby
class Source
  left: Int

  def has_more -> Bool
    @left > 0
  end
end

async def next_chunk(s: &Source) -> Int
  1
end

async def drain(source: &Source, acc: Int) -> Int
  if !source.has_more
    return acc
  end
  chunk = next_chunk(source).await
  drain(source, acc + chunk).await
end
```

## Notes
- The check fires at every `.await` site whose enclosing loop body is
  a `while` / `until` / `for` / `loop` body. `.await` inside an
  `if` or `case` branch within an async method is fine — those branches
  become separate states per spec §B11.
- Spec: [docs/specs/syntax/async_lowering.spec.md](../specs/syntax/async_lowering.spec.md) §B11 (note on `while`/`for`) and "Reserved error codes" §E1115.
