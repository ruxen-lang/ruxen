# E0615: auto-synth Hashable: field type is not hashable

## Why
A hash key (the `K` of `Hash[K, V]`, the element of `Set[T]`) must be
hashable, and so must every field of a type that says
`include Hashable`. Primitives (`Int`, `Float`, `Bool`, `Char`) and
`String` are hashable, and so is a user type whose fields all are. The
collections `Array`, `Hash` and `Set` are not (their contents can
change while they sit in the table), and neither is an opaque C handle
such as `Mutex[Int]`.

E0615 fires in two places: on a `Hash` or `Set` type whose key or
element type is not hashable, and on a type that says
`include Hashable` with a field that is not.

`include Hashable` is Rust vocabulary and is [deprecated]; hash keys
will use Ruby's `hash` and `eql?` methods
[planned](../../TODO.md#t-d8).

## Example

Rejected with E0615 [implemented]:

```ruby
def remember(seen: Set[Array[Int]])     # Array is not hashable
  puts seen.size
end
```

A [deprecated] `include Hashable` over a C handle field, rejected with E0615:

```ruby
class Sample
  id: Int
  lock: Mutex[Int]       # a C handle: not hashable
  include Hashable
end
```

## Fix
Key the table by a hashable value, such as a `String` built from the
row, or drop the field that cannot be hashed.

Compiles [implemented]:

```ruby
def remember(seen: Set[String])
  puts seen.size
end
```
