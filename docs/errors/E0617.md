# E0617: auto-synth Ord: field type does not satisfy Ord

## Why
A synthesized `Ord` provides a lexicographic ordering over the fields
in declaration order, so every field type must itself be ordered.
Primitives (`Float` included: it compares by IEEE-754), `String` and
user types whose fields all qualify are ordered; an opaque C handle
such as `Mutex[Int]` is not.

`Ord` (with `Eq`, `PartialEq` and `PartialOrd`, which it needs, E0606)
is Rust vocabulary and is [deprecated]. The Ruby form is
`include Comparable` with a `<=>` method that compares the fields you
choose.

## Example

A [deprecated] `include Ord` over a C handle field, rejected with E0617:

```ruby
class Job
  rank: Int
  lock: Mutex[Int]          # a C handle: not ordered
  include PartialEq
  include Eq
  include PartialOrd
  include Ord
end
```

## Fix
Include `Comparable` and order on the fields that have an order.

Compiles [implemented]:

```ruby
class Job
  rank: Int
  lock: Mutex[Int]
  include Comparable

  def <=>(other: &Job) -> Int
    @rank <=> other.rank
  end
end
```
