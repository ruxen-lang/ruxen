# E0704: kind mismatch on const-generic argument

## Why
A generic parameter declared with `const N: Type` accepts only a
**const-valued** argument at the use site (an integer literal,
in-scope const-param reference, or simple arithmetic over those).
Conversely, a plain `T` type parameter accepts only a **type**
argument.  When the kinds disagree — a const literal lands in a
type slot or (in the inverse direction) a type lands in a const
slot — resolve rejects the call before unification ever sees the
malformed instantiation.

## Example
```rvn
class HoldsType[T]
  x: T
end

def main
  # `4` is a const literal; the slot expects a type.
  let _h: HoldsType[4] = HoldsType.new   # error[E0704]
end
```

## Fix
Pass the kind the slot was declared with.  For the example above,
either drop the const-generic position or change the parameter
declaration to a const param:

```rvn
class HoldsFour[const N: USize]
  buf: [Int; N]
end

def main
  let _h = HoldsFour[4].new   # ok — N is now a const param
end
```

## Notes
- This is distinct from **E0701** (right kind, wrong type — e.g.
  `Bool` passed at a `USize`-typed const slot), **E0702** (non-const
  expression in a const slot), and **E0703** (const-arg arithmetic
  overflowed during evaluation).
- Historical note: E0704 was originally assigned E0700 by the
  const-generics spec, but the typeck iterator-`sum` validator was
  already emitting E0700 for an unrelated case.  The spec was
  amended 2026-05-14 to fork the two; this code is the new home for
  the kind-mismatch diagnostic.
