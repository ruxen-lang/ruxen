# E0727: type name collides with a built-in / stdlib type; rename it

## Why

Ruxen currently uses a **flat global symbol namespace**: every type lowers its
methods to mangled symbols like `Signal_clone`, `Signal_init`, regardless of
which package declared the type. The standard library is auto-loaded into every
program, so its type names (`Signal`, `Runner`, `Mutex`, `String`, …) are
already taken.

If your program declares a type whose name matches a built-in or stdlib type,
both definitions try to emit the same mangled symbols (e.g. two `Signal_clone`
functions) and the build fails much later with a cryptic codegen error
(`Failed to define function 'Signal_clone': DuplicateDefinition`). E0727 fires
at **resolve time** instead, naming the collision so you can rename your type
immediately rather than chasing a linker/codegen failure.

## Example

```ruxen
# std.sync already exports `Signal`, which is auto-loaded.
class Signal[T: Send]      # error[E0727]: `Signal` collides with a stdlib type
  cell: SharedSync[Mutex[T]]
  def init(@cell: SharedSync[Mutex[T]]) end
end
```

## Fix

Rename your type to something the standard library does not already use:

```ruxen
class State[T: Send]       # OK — distinct name
  cell: SharedSync[Mutex[T]]
  def init(@cell: SharedSync[Mutex[T]]) end
end
```

Until per-package symbol namespacing lands, treat stdlib type names
(`Signal`, `Runner`, `Mutex`, `Arc`, `String`, `File`, …) as reserved.
