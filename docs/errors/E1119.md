# E1119: block parameter `&block` must be the last parameter

## Why
A Ruby-style block is the **implicit trailing argument** of a call: when you
write `fn(a, b) do … end`, the block attaches after every positional argument.
A function therefore declares its block as the final parameter with the `&`
sigil:

```rx
def each(xs: Array[Int], &block: Fn[(Int) -> nil])
  ...
end
```

If `&block` were not last, a positional argument after it could never be
supplied at a call site (the block already occupies the trailing slot), so the
declaration is contradictory. The compiler rejects it rather than silently
accept an uncallable signature.

See [docs/decisions/ruby-block-semantics.md](../decisions/ruby-block-semantics.md)
(decision D4).

## Example
```rx
def bad(&block: Fn[() -> nil], x: Int)    # error[E1119]: `x` follows `&block`
  yield
end
```

## Fix
Move `&block` to the end, after all positional parameters:

```rx
def good(x: Int, &block: Fn[() -> nil])
  yield
end
```

## Notes
- A `&block` parameter is always **optional** at call sites — calling without a
  block is legal, `block_defined?` is then `false`, and reaching a `yield` with
  no block is a runtime error (a clean panic naming the function), not a
  segfault.
- The canonical block-type spelling is `Fn[(T…) -> R]` (square brackets); the
  paren form `Fn(T…) -> R` is also accepted.
