# E0748: the result's borrow source is ambiguous

## Why

A function whose result holds a reference (`-> &A`, `-> Array[&String]`)
hands back something borrowed. The compiler reads what it borrows from the
signature, as Rust's lifetime elision does, so no lifetime is ever spelled:

- a method's result borrows from its receiver (`self`);
- a function without a receiver borrows from its one reference parameter.

A function with no receiver, several reference parameters and an unnamed
reference in its result has no single source (Rust reports E0106 here).
Every caller relies on knowing which argument stays borrowed while the
result is in use, so the declaration is rejected.

## Example

Rejected with E0748 [implemented]:

```ruby
# error[E0748]: `pick` returns `&A`, which holds a reference, but it has no
# receiver and 2 reference parameters (`a`, `b`), so which one the result
# borrows from is ambiguous
def pick(c: Bool, a: &A, b: &A) -> &A
  if c
    a
  else
    b
  end
end
```

## Fix

Make it a method of the value it borrows from, return an owned value, or
name the lifetime (the rare escape hatch): the result then borrows every
parameter whose reference carries that name.

Accepted [implemented]:

```ruby
def pick[a](c: Bool, x: &a A, y: &a A) -> &a A
  if c
    x
  else
    y
  end
end
```

Or as a method.

Accepted [implemented]; `def init` is [deprecated]: its replacement `initialize` is [planned](../../TODO.md#t-initialize):

```ruby
class A
  name: String

  def init(@name: String)
  end

  def either(c: Bool, other: &A) -> &A
    if c
      self
    else
      other
    end
  end
end
```

A method's body may still return another reference parameter (`other`
above, though elision names the receiver): the body is not yet checked
against its signature, so the caller borrows what the body returns as well,
found by following the body through every call it returns from. Here
`pick.either(c, &b)` keeps both `pick` and `b` borrowed while the result is
used.
