# E1020: cannot rebind a `&var` parameter that holds a handle

## Why
How a `&var T` parameter reaches the caller depends on `T`
(`mir/refmut_abi.rs`):

- for a String or a scalar (every integer and float width, `Bool`, `Char`)
  it is the **address of the caller's variable**, so `n += 1` or `s = "x"`
  in the callee writes the caller's variable;
- for every other type (a class, struct, enum, `Array`, `Hash`, `Set`, a
  closure, or a type parameter) it is the caller's **handle**: the callee can
  mutate the object through it (`p.x = 1`, `items.push(v)`), but it holds its
  own copy of the handle word.

Assigning a new value to such a parameter (`p = Point.new(0, 0)`,
`items = [1, 2]`, `items += [3]`) would only change the callee's copy. The
caller would still see its old object, so the assignment would silently do
nothing. It is rejected instead.

## Example
```rx
class Point
  x: Int
  def init(@x: Int)
  end
end

def reset(p: &var Point) -> nil
  p = Point.new(0)   # E1020: the caller never sees the new Point
end
```

## Fix
Return the new value and let the caller rebind its own variable:

```rx
def reset -> Point
  Point.new(0)
end

def main
  var p = Point.new(5)
  p = reset
  puts(p.x)
end
```

Or mutate the object through the handle, or keep the value in a field of an
object the callee can reach:

```rx
def reset(p: &var Point) -> nil
  p.x = 0
end

class Slot
  point: Point
  def init(@point: Point)
  end
end

def reset_slot(slot: &var Slot) -> nil
  slot.point = Point.new(0)
end
```

A `&var Int` or `&var String` parameter may be assigned: it writes the
caller's variable.
