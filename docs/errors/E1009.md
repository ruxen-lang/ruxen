# E1009: cannot move value — currently borrowed

## Why
A live borrow points into the value, so moving it, assigning to it, or
assigning to any field or element of it would free or replace what the
borrow still reads.

A binding borrows from every place its value may come from (TODO.md
Decisions, "Fields" and "Borrow of a temporary"): `x = u.name` borrows `u`
at `name`, and so do `x = u.label` (a method returning `&String`),
`x = if c then u.name else v.name end` (both `u` and `v`), a `case` or block
whose result is such a read, a parallel assignment `x, n = u.name, 1`, a
copy `y = x`, and a closure that captures `x` (for as long as the closure
lives). A `for` loop over `l.names` borrows it until the loop ends. The
borrow lasts until the binding's last use.

While it lasts, these are E1009:

- moving the root (`eat(u)`, `w = u`);
- assigning the root, a field of it on the same path (`u.name = ..`,
  `u = ..`), or an element of a borrowed collection, with `=`, `op=` or as a
  parallel-assignment target;
- writing through an alias of a sub-object: `b = u.a; b.name = ..` writes
  `u.a.name`.

Writing a different field (`u.count += 1` while `u.name` is borrowed) is
fine. A `var self` call or a `&var` argument on the borrowed place is the
mutable-borrow form of the same conflict (E1002).

## Example
```rx
class User
  name: String
  def init(@name: String)
  end
end

u = User.new("ann")
x = u.name
u.name = "bob"   # E1009: `x` still reads the old name below
puts x
```

## Fix
Use the borrow before the write, or clone what you read:

```rx
u = User.new("ann")
x = u.name
puts x
u.name = "bob"   # fine: `x` is no longer used

y = u.name.clone
u.name = "cid"
puts y           # fine: `y` owns its copy
```
