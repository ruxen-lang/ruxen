# E1015: type does not satisfy a declared mixin bound

## Why
A generic parameter declared with a mixin bound — `def f[T: Bound](...)`,
`class C[T: Bound]`, or `... where T: Bound` — promises that every concrete
type substituted for `T` satisfies `Bound` (it `include`s the mixin, or
structurally provides the mixin's required methods for a `some`-dispatched
position). The compiler enforces that promise at each call/construction
site: once `T` is bound to a concrete type by the actual arguments, the
concrete type is checked against every declared bound.

E1015 is the *general* form of this check. A handful of bounds carry their
own dedicated code for a more specific message:

* `T: Send` → **E1011** (or **E1101**/**E1102** at `Mutex`/`Arc`/`SharedSync`
  construction sites);
* `T: Sync` → **E1012**;
* the numeric `Add` bound on `sum` → **E0700**.

Every other unsatisfied mixin bound surfaces as E1015.

## Example
```rx
mixin Greet
  def greet -> String
end

class Greeter
  include Greet
  def greet -> String
    "hi"
  end
end

class Plain
end

def needs[T: Greet](x: &T) -> String
  x.greet
end

def main
  let p = Plain.new()
  let _r = needs(&p)   # error[E1015]: `Plain` does not satisfy `Greet`
end
```

## Fix
Make the concrete type satisfy the bound, or pass a type that already does:

* **`include` the mixin** on the type and implement its required methods:
  ```rx
  class Plain
    include Greet
    def greet -> String
      "plain"
    end
  end
  ```
* **Pass a type that satisfies the bound** (e.g. `Greeter` above).
* **Relax the bound** if the function does not actually rely on it — drop
  `: Greet` from the generic parameter so the call site is unconstrained.

## Notes
- Only parameters/generics that *declare* a bound are checked; an unbounded
  generic (`def f[T](...)`) is never flagged by E1015.
- An abstract `T` value (inside another generic that forwards it) is not
  flagged here: it is satisfied when `T` itself declares the same bound, and
  otherwise checked where `T` is bound to a concrete type.
- Emitted by `typeck::infer::ops::check_declared_bounds` (param-typed seam)
  and `check_generic_param_bounds` (the harvested-generic seam, Feature B).
