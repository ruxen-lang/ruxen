# E0732: nil-coalescing operator requires Option and a matching fallback

## Why

The `??` operator unwraps a `T?` or evaluates a fallback value when the
value is `nil`. Its left operand must therefore be a `T?`, and its right
operand must produce `T`.

`??` is [deprecated]; the Ruby form is `a || b`, which needs truthiness
on a `T?` and is [planned](../../TODO.md#t-truthiness).

## Example

The [deprecated] `??` with an `Int` on the left, rejected with E0732:

```ruby
value = 1 ?? 2
# error[E0732]: `??` requires an Option on the left
```

## Fix

Use a `T?` on the left and a fallback with the contained type.

Works today, with the `??` that is [deprecated] (replaced by `configured() || 2`):

```ruby
def configured -> Int?
  nil
end

value = configured() ?? 2
puts value
```

The fallback is lazy. It is evaluated only when the left operand is `nil`.
Chained fallbacks associate to the right, so `a ?? b ?? value` works when both
`a` and `b` are `T?`.
