# E1101: Mutex / Sender / Receiver requires Send payload

## Why
`Mutex[T]`, `Sender[T]`, `Receiver[T]`, and `channel[T]()` carry
values across thread boundaries. The contained type `T` must
implement `Send`. The compiler found a construction whose payload
type does not.

See [docs/specs/ownership/send_sync_enforcement.spec.md](../specs/ownership/send_sync_enforcement.spec.md)
§B3, §B5 for the rule.

## Example
```rvn
class Foo
  def init
  end
end

def main
  let f = Foo.new
  let _m = Mutex.new(f)   # E1101: Foo is not Send
end
```

## Fix
User classes are not auto-derived for `Send` in v1. If the class is
genuinely safe to share across threads, add an explicit `include
Send`:

```rvn
class Foo
  include Send
  def init
  end
end
```

For classes wrapping raw pointers or non-Send foreign handles, use
`unsafe include Send` to manually assert safety:

```rvn
class WrapsRawPointer
  unsafe include Send
  def init
  end
end
```

A class declared `include !Send` (negative include) explicitly opts
out and is rejected here regardless of its fields.
