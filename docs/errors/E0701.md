# E0701: const-generic argument does not fit declared type

## Why
A generic parameter declared `const N: TY` accepts only values of
type `TY`.  When the kind matches (a const argument lands in a const
slot) but the value can't be represented by `TY`, resolve rejects
the instantiation here rather than allowing a silently-truncated /
wrap-around value to flow downstream.

Reachable cases in v1:

- `const N: Bool` with an int literal other than `0` or `1`.
- Unsigned-family const params with a negative literal (the parser
  doesn't emit negatives today, but the check is defensive in case
  a future arithmetic path produces one).

Future cases (once the parser accepts wider const-expression
shapes):

- `const N: UInt8` with a literal larger than `255`.
- `const N: Int8` with a literal larger than `127` or smaller than
  `-128`.

Distinct from **E0704** (kind mismatch — type vs. const slot) and
**E0702** (non-const expression in const slot).

## Example: Bool slot, non-boolean literal
```rvn
class Logger[const VERBOSE: Bool]
end

def main
  let _l = Logger[5].new   # error[E0701]: 5 does not fit `Bool`
end
```

## Fix
Pass a value the declared type can represent:

```rvn
let _l = Logger[1].new   # 1 = "on" is fine
let _t = Logger[0].new   # 0 = "off" is fine
```

For sized-integer const params, choose a literal inside the type's
range:

```rvn
class Buf[const N: UInt8]
end

def main
  let _b = Buf[200].new   # ok (0..=255)
  # Buf[300].new          # error[E0701] once wider literals land
end
```

## Notes
- Bool's "fits" check is `value == 0 || value == 1` — matches the
  `false`/`true` projection used elsewhere in the language.
- For arithmetic const-args (`Counter[2 + 3]`), the check applies
  to the **folded** value after the S8.S4 normal-form pass.
- The diagnostic message names the offending value and the
  declared type so the user can see exactly which value was
  rejected and what shape was expected.
