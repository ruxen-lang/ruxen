# E0701: wrong const-arg type (reserved)

**Status:** reserved by `docs/specs/types/const-generics.spec.md`
§"Error code reservations".  No emit site today; planned to fire
when the const-arg passed at a use site has the wrong underlying
type (e.g. `Bool` where `USize` is declared).

## Why (planned)

A generic parameter declared `const N: USize` accepts only
`USize` values.  Passing `true` (a `Bool`) or `3.14` (a `Float`)
at the use site is a kind-conformant but type-incorrect substitution
— resolve walks the declared param type and rejects the mismatch
before the surrounding type ever participates in unification.

## Example (planned)

```rvn
struct Vector[T, const N: USize]
  data: [T; N]
end

def main
  let _v = Vector[Int, true].new   # error[E0701]: expected USize, got Bool
end
```

## Fix (planned)

Pass an integer literal (or in-scope const-`USize` parameter) at
the const slot:

```rvn
let _v = Vector[Int, 4].new
```

## Notes

- Distinct from **E0700** (kind mismatch — type vs. const slot):
  E0700 fires when a *type* is passed where a *const* is declared
  (or vice versa); E0701 fires when the *kind* matches but the
  *type of the value* doesn't.
- Tracking: spec §B5 (S5 wiring shipped without E0701 emission —
  the kind-mismatch check at resolve/mod.rs:4757-4768 currently
  uses E0700 for both kind and type mismatches; splitting the
  diagnostics is a follow-up).
- `Float*` const generics are non-goal NG2; an attempt to pass a
  float-typed const param surfaces here too.
