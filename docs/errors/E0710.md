# E0710: IoError variant constructor wrong arity

## Why
`IoError` is a tagged enum whose variants come in two shapes:

- **Unit variants** (`NotFound`, `PermissionDenied`, `AlreadyExists`,
  `Interrupted`, `WouldBlock`, `InvalidInput`, `UnexpectedEof`,
  `BrokenPipe`) — no fields.
- **Struct variants** carrying a single `message: String` field
  (`Other`, `ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`,
  `NotConnected`, `AddrInUse`, `AddrNotAvailable`, `InvalidData`,
  `TimedOut`, `WriteZero`, `Unsupported`, `OutOfMemory`).

A constructor call with the wrong shape — passing an argument to a
unit variant, or omitting / mis-naming the `message:` field on a
struct variant — is rejected here.

## Example
```rx
# error[E0710]: `IoError.NotFound` is a unit variant; it takes no fields
let e = IoError.NotFound("oops")

# error[E0710]: `IoError.ConnectionRefused` expects field `message: String`
let e = IoError.ConnectionRefused()
```

## Fix
Construct with the right shape:

```rx
let e = IoError.NotFound
let e = IoError.ConnectionRefused(message: "connection refused")
```

## Notes
- The 20 IoError variants are listed in
  `crates/ruxen-core/src/resolve/mod.rs` under the `IoError`
  registration block; the matching runtime constants live in
  `crates/ruxen-core/runtime/runtime.c` (`RUXEN_IO_ERROR_*`).
- Tag values are stable and append-only — new variants are added at
  the end of the discriminant order so existing match-on-tag code
  keeps working.
- `IoError.kind() -> IoErrorKind` returns the discriminant as a
  20-unit-variant sibling enum if you want to branch on the variant
  without binding the payload.
