# E0710: IoError variant constructor wrong arity

## Why
`IoError` is a tagged enum whose variants come in two shapes:

- **Unit variants** (`NotFound`, `PermissionDenied`, `AlreadyExists`,
  `Interrupted`, `WouldBlock`, `InvalidInput`, `UnexpectedEof`,
  `BrokenPipe`) — no fields.
- **Struct variants** carrying a single `message: String` field
  (`Other`, `ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`,
  `NotConnected`, `AddrInUse`, `AddrNotAvailable`, `InvalidData`,
  `TimedOut`, `WriteZero`, `Unsupported`, `OutOfMemory`).

The intended check rejects a constructor call with the wrong shape:
passing an argument to a unit variant (`IoError.NotFound("oops")`), or
omitting the `message:` field on a struct variant
(`IoError.ConnectionRefused()`).

This code is registered but not emitted today: no compiler stage
reports it, and the type checker accepts both wrong shapes above.
Write the shapes below.

## Example

The right shapes compile [implemented]:

```ruby
e = IoError.NotFound
e2 = IoError.ConnectionRefused(message: "connection refused")
puts e2.message
```

`enum` with payload variants is [deprecated]; the replacement is one
`Data` type per variant, [planned](../../TODO.md#t-data-define).

## Fix
Call a unit variant with no arguments (`IoError.NotFound`) and give a
struct variant its `message:` field
(`IoError.TimedOut(message: "read timed out")`).

## Notes
- The 20 IoError variants are declared in the `io` package of the
  standard library (`library/std/io/src/lib.rx`).
- Tag values are stable and append-only — new variants are added at
  the end of the discriminant order so existing match-on-tag code
  keeps working.
- `IoError#kind -> IoErrorKind` returns the discriminant as a
  20-unit-variant sibling enum if you want to branch on the variant
  without binding the payload.
